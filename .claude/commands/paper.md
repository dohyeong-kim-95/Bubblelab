# /paper — 논문 하나를 붙들고 이해될 때까지 판다

**이 세션은 논문 하나만 본다.** 다른 일을 같이 하지 않는다 — 이해가 안 되는 논문을
붙들고 질문을 많이 하는 자리라, 컨텍스트를 논문과 오간 질문으로만 채운다.
개발이나 배포 이야기가 나오면 "그건 리포 세션에서 하자" 고 말하고 논문으로 돌아온다.

```
/paper 2608.19808     번호로 시작
/paper                오늘 다이제스트에서 고르게 해준다
/paper 정리           지금 붙들고 있는 것을 끝내고 life/papers 에 남긴다
```

`life/papers` 에 글이 남는 **유일한 길**이다. 디스코드 봇은 여기 쓰지 못한다 —
저기는 초록만 보고 거르는 자리고, 여기 남는 것은 **사람이 직접 이해한 논문**이다.

## ① 준비 — 내 문제부터 받아 온다

리포 밖에서도 열리므로 "내 문제" 를 서버에서 받는다. 명령 파일에 베껴 두지 않는다
(고치면 어긋난다).

```bash
set -a && . ~/.bubblelab/papers.env && set +a
curl -s -H "Authorization: Bearer $PAPERS_SINK_SECRET" \
  https://life.bubblelab.dev/_papers/profile
```

번호가 없으면 오늘 것을 보여주고 고르게 한다:

```bash
curl -s https://life.bubblelab.dev/_papers/latest
```

## ② 읽기 — 전문을 본다

초록으로 때우지 않는다. 초록만 볼 거면 디스코드에서 이미 봤다.

```bash
curl -sL "https://arxiv.org/pdf/<번호>" -o "/tmp/<번호>.pdf"
```

Read 도구로 읽는다(PDF 를 직접 읽는다. 10쪽이 넘으면 `pages` 로 나눠 받는다).
**본문을 끝까지 읽는다** — 실험 설정과 부록에 쓸 만한 게 있고, 초록에는 그게 없다.

읽고 나서 이렇게 연다:

- 한 문단으로 무엇을 한 논문인지
- **내 문제와 부딪히는 지점 두세 개**
- "여기부터 물어보면 된다" 는 자리 세 개

**초록만 보고 내렸던 판단이 틀렸으면 그것부터 말한다.** 전문을 읽는 이유가 그거다.

## ③ 질의응답 — 여기가 본론이다

이해될 때까지 붙어 있는 게 이 명령의 목적이다.

- **모르면 모른다고 한다.** 논문의 어디를 같이 보면 되는지 말하고, 지어내지 않는다.
- 사용자가 같은 것을 다시 물으면 설명이 나빴던 것이다. 각도를 바꿔 다시 말한다.
- 수식은 기호를 하나씩 풀어서 말한다. 논문 표기를 그대로 옮기지 않는다.
- 사용자가 "알겠다" 고 할 때까지 다음으로 넘어가지 않는다.

## ④ 남기기 — 이해한 것만

`/paper 정리` 라고 하거나 대화가 마무리되면 남긴다. **사용자가 실제로 물은 것과
스스로 내린 결론이 들어가야 한다** — 그게 이 글을 기계 요약과 가르는 부분이다.
물은 게 하나도 없으면 남기지 말고 "아직 붙들고 있는 중" 이라고 한다.

일곱 항목은 이대로 쓴다:

무엇을 한 논문인가 · 핵심 방법 · 전제와 가정 · 실험 설계 · 내 문제 적용 ·
따라 해볼 것 · 한계와 의심

```bash
curl -s -X POST https://life.bubblelab.dev/_papers/reviews \
  -H "Authorization: Bearer $PAPERS_SINK_SECRET" \
  -H "Content-Type: application/json" \
  -d @payload.json
```

```json
{
  "paper":   { "id": "2608.19808", "title": "…", "link": "https://arxiv.org/abs/2608.19808",
               "published": "2026-08-20", "authors": ["…"] },
  "source":  "full",
  "review":  { "무엇을 한 논문인가": "…", "핵심 방법": "…" },
  "asked":   ["사용자가 실제로 물은 것을 그대로", "…"],
  "verdict": "사용자가 내린 결론. 대신 지어내지 말 것 — 애매하면 물어서 받는다."
}
```

- `source` 는 `full`(전문) 이나 `abstract`. **전문을 안 읽었으면 `full` 이라고 하지 않는다.**
- `asked` 는 **사용자의 말**이다. 내가 던진 물음을 넣지 않는다.
- `verdict` 도 사용자의 것이다. 대화에서 분명히 나오지 않았으면 한 줄 물어서 받는다.

남긴 뒤 `https://life.bubblelab.dev/papers` 를 알려주고, **이 세션은 여기서 끝난다**고
말한다. 다음 논문은 새 세션에서 연다 — 그래야 컨텍스트가 논문 하나로 유지된다.
