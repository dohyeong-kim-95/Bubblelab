# www — Bubblelab 랜딩

상태: **Beta**. 공개 프로젝트의 상태와 시작점을 안내하는 메인 화면입니다.

`www/index.html`은 <https://bubblelab.dev>와 <https://www.bubblelab.dev>에 제공되는
가벼운 정적 랜딩 페이지입니다.

현재 랜딩은 다음 카테고리를 소개합니다.

- `slop`: 짧은 게임과 실험
- `mindfulness`: 짧은 호흡·소리·생각 알아차림
- `games`: 현재 실시간 서버 정비로 Archived 상태
- `util`: 일상 도구
- `idle`: 7일 방치형 게임

`assets`, `invest`, `admin`도 독립 서브도메인으로 배포되지만 랜딩 목록에는 아직
노출하지 않습니다. 새 공개 카테고리를 랜딩에 보여주려면 `www/index.html`의 목록을
직접 수정해야 합니다. 빌드 스크립트가 이 페이지의 링크를 자동 갱신하지는 않습니다.

현재 `www/index.html`의 문구와 링크는 초기 랜딩이므로, 공개 준비의 다음 단계에서
대표 문장, 추천 실험, 상태가 표시된 카테고리, 최근 업데이트, 운영자 소개 구조로
개편해야 합니다. Archived 카테고리를 링크할 때는 정비 중임을 화면에도 표시합니다.

## 카드 검색 (룰베이스)

랜딩 상단의 검색창은 **카테고리 카드 + 모든 공개 서브도메인의 카드**를 한 번에
찾습니다. 서버도 AI도 쓰지 않고 규칙과 점수만으로 고릅니다 — 규칙 엔진은
`_shared/search-rules.js`(브라우저와 Node 테스트가 같이 씀), 검사는
`_infra/search-rules.test.mjs`.

규칙은 센 순서로 이렇습니다. 앞의 두 개로 안 걸릴 때만 뒤가 동작하고, 결과 카드에는
왜 걸렸는지 알기 어려운 규칙(초성·자모·오타·비슷한 말)만 이름표가 붙습니다.

| 규칙 | 예 |
| --- | --- |
| 정확 일치 | `lotto` → lotto |
| 앞부분 일치 | `사다` → 사다리타기 |
| 부분 일치 | `다리타기` → 사다리타기 |
| 초성 일치 | `ㅅㄷㄹ` → 사다리타기 |
| 자모 일치 | `사다ㄹ` → 사다리타기 (한 글자 덜 친 상태) |
| 오타 교정 | `tkekfl` → 사다리타기 (한/영 안 바꾸고 침) |
| 비슷한 말 | `제비뽑기` → 사다리타기 (`SYNONYMS` 표) |

띄어쓴 낱말은 **모두** 맞아야 하고(`네컷 사진`), 못 찾으면 아무거나 내지 않습니다.

**색인은 빌드가 자동으로 채웁니다.** `_infra/build.mjs`가 각 카드 페이지의
`<title>`(대개 한국어)과 폴더 이름(영문)을 모아 `www/index.html`의
`<script type="application/json" id="bl-cards">`에 그대로 심습니다. 토이를 추가할 때
따로 등록할 것은 없습니다. `SYNONYMS`만 손으로 관리하는데, 제목에도 폴더 이름에도
없는 말로 찾아오게 하고 싶을 때만 한 줄 늘리면 됩니다.

**감춘 것은 검색에서도 감춥니다.** 색인은 카테고리 홈 카드와 같은 기준
(`CONFIDENTIAL_SUBDOMAINS`·`UNLISTED_ENTRIES`)으로 걸러지고, 검색이 뒷문이 되지
않는지는 `_infra/home-button.test.mjs`가 매 빌드마다 확인합니다.

카테고리 카드 목록은 정적 HTML 그대로 두고 스크립트가 DOM에서 읽습니다 — 색·설명·
주소를 두 벌 두지 않기 위해서고, 스크립트가 죽거나 막혀도 랜딩은 원래대로 보입니다
(검색창만 사라짐).

**검색창만 다크모드에서도 흰 종이입니다.** 랜딩에서 제일 먼저 눈에 띄어야 하는
입력칸이라 배경을 테마와 함께 어둡게 두지 않았습니다. 대신 글자·플레이스홀더·지우기
버튼 색을 상속받지 않고 직접 정합니다 — `light-dark()`나 `color: inherit`으로 두면
다크모드에서 흰 바탕에 흰 글씨가 됩니다.

## 데이터

검색어는 브라우저 안에서만 쓰이고 서버로 보내지 않습니다(색인이 페이지 안에 있어
검색 중 네트워크 요청이 없습니다). 저장하거나 기록하지도 않습니다. 그 밖에는 일반
공개 페이지와 동일하게 익명 브라우저 ID 기반 방문 집계가 적용될 수 있으며
관리자·Planner·실시간 데이터는 노출하지 않습니다.
