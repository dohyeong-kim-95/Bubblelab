Custom Skills
Reusable markdown prompts you invoke with a single slash command.
Why for you: You ran the same build → test → commit → deploy → verify loop across nearly every session (76 commits, 986 Bash calls), and the verification step is exactly where things broke twice — codify it once so it runs the safe way every time.
# .claude/skills/ship/SKILL.md --- name: ship description: Build, test, commit, deploy to Cloudflare, and read-only verify --- 1. Run the test suite; stop and report if anything fails. 2. `git status` — stage ONLY files you edited this session. Never `git add .` 3. Commit with a concise Korean-or-English message describing the user-facing change. 4. `git push origin main` 5. Deploy: `npx wrangler deploy` 6. Verify READ-ONLY: `curl -s -o /dev/null -w "%{http_code}" <PROD_URL>` plus a GET of the health/status endpoint. NEVER POST test payloads to production. 7. If verification fails, report the exact failure and propose a rollback command — do not auto-rollback without asking.
Hooks
Shell commands that auto-run at lifecycle events like before/after edits or commands.
Why for you: Your top friction category is 'buggy_code' (10 occurrences) shipped to prod — a PostToolUse hook that lints/typechecks after every Edit catches CSS specificity and JS mistakes before deploy, and a PreToolUse guard can block `git add .` outright.
// .claude/settings.json { "hooks": { "PostToolUse": [ { "matcher": "Edit|Write", "hooks": [ { "type": "command", "command": "npx prettier --write \"$CLAUDE_FILE_PATHS\" 2>/dev/null; npm run lint --silent || true" } ] } ], "PreToolUse": [ { "matcher": "Bash", "hooks": [ { "type": "command", "command": "grep -Eq 'git add (\\.|-A|--all)' <<< \"$CLAUDE_TOOL_INPUT\" && { echo 'Blocked: stage individual files only'; exit 2; } || exit 0" } ] } ] } }
