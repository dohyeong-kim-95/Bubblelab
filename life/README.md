# LIFE

`life.bubblelab.dev` — 앱 이름은 **LIFE**. 목록 여러 개를 좌우로 넘기며 쓰는 할 일 앱. 안드로이드에서
홈 화면에 추가해 PWA 로 쓰는 것을 기준으로 만들었다.

## 경계

**서버에 아무것도 저장하지 않는다.** 할 일은 브라우저 `localStorage`(`bl_life_v1`)에만
있다. 워커가 하는 일은 비밀번호 게이트(`bl_life` 쿠키)뿐이고, `/_life/*` 같은 API 는
없다. 기기끼리 동기화되지 않는다 — 폰에서 적은 것은 폰에만 있다.

브라우저 데이터를 지우면 함께 사라진다. 백업은 아직 없다.

## 조작

- 제목(왼쪽 위)을 **한 번 누르면 목록 선택**, **두 번 누르면 이름 바꾸기**다.
  같은 자리에 두 동작이 겹치므로 단일 탭을 250ms 미뤄 두 번째 탭을 기다린다 —
  더 짧으면 더블탭을 놓치고, 길면 목록 선택이 굼떠 보인다.
- 키보드로는 탭 횟수를 셀 수 없어 Enter 는 목록 선택만 한다. 이름 바꾸기는 `⋯`
  메뉴에도 있다.
- 좌우 스와이프로 목록을 넘긴다. 점을 눌러 이동해도 된다. 점은 스크롤이 멈추기를
  기다리지 않고 매 프레임(rAF) 따라온다.
- **미완료가 항상 위, 완료가 항상 아래**다. 저장된 배열은 그대로 두고 보여줄 때만
  나누므로(`orderedItems`), 완료를 취소하면 원래 자리로 돌아온다.

## 도구 연결

할 일마다 도구를 하나 붙일 수 있다. 이름이 그대로 주소가 된다.

- **길게 누르기(0.5초)** — 도구 이름을 적는다. 비우면 연결이 끊긴다.
- **두 번 누르기** — 연결된 도구를 연다. 없으면 연결 화면이 열린다.
- 이름은 슬러그만 받는다(`[a-z0-9-]`, 32자). 주소에 그대로 들어가므로
  `javascript:` 나 `../` 같은 것이 섞이지 않게 `store.js` 에서 막는다.

도구는 **`life/<이름>/index.html`** 로 만든다. 리포에 폴더를 더하면 배포되고, 지우면
사라진다. 같은 게이트 뒤에 있으므로 로그인도 그대로 물려받고, PWA scope 안이라
설치된 앱 안에서 열린다(주소창 없이). 돌아올 때는 뒤로 가기.

**도구를 만들 때 주의할 것 두 가지**

1. **인라인 스크립트·스타일이 막혀 있다.** life 의 CSP 는 `script-src 'self'` 라
   `<script>…</script>` 와 `onclick=` 은 실행되지 않는다. 반드시 별도 `.js` 파일로
   빼서 `<script type="module" src="app.js">` 로 부른다. (AI 로 만들면 인라인으로
   쓰는 경우가 많으니 먼저 확인할 것.)
2. **외부 호스트가 전부 막혀 있다.** CDN 에서 라이브러리·폰트를 불러올 수 없다.

## 만듦새

- `store.js` 가 상태를 전부 맡는다(순수 함수). 화면과 `_infra/life.test.mjs` 가
  같은 모듈을 쓰므로 목록·항목 규칙을 화면 안에서 따로 만들지 않는다.
- 좌우 이동은 CSS `scroll-snap` 이 맡는다. 드래그를 직접 처리하지 않아야 관성·
  되돌아가기·접근성이 브라우저 것 그대로 나온다. 스크롤이 멈추면 헤더와 점만 맞춘다.
- 목록 최대 12개, 이름 24자, 항목 200자. `store.js` 상단에 모여 있다.
- 키보드가 올라오면 앱을 덮지 않고 앱이 그만큼 줄어든다. 뷰포트 meta 의
  `interactive-widget=resizes-content` 가 그 선언이고, 이를 지원하지 않는 브라우저를
  위해 `visualViewport` 로 `--app-h` 를 채운다. 문서 스크롤은 만들지 않는다
  (`body { overflow: hidden }`).
- 항목 하나가 바뀌면 그 목록만 다시 그린다(`update(next, listId)`). 전체를 다시
  그리면 목록이 길어질수록 지연으로 느껴지고 스크롤 위치까지 튄다.
- 테마는 검은 바탕에 흰 글씨 하나다(`color-scheme: dark`). 색으로 강조하지 않고
  밝기로만 나눈다. 상태바·스플래시가 함께 검게 나오도록 `theme-color` 와 manifest 의
  `background_color`·`theme_color` 도 `#000000` 이다.
- **설치되려면 매니페스트와 아이콘이 게이트 앞에 있어야 한다.** 크롬은 설치 조건을
  볼 때, WebAPK 를 구울 때는 구글 서버가 이것들을 **쿠키 없이** 받아 간다. 로그인
  페이지 HTML 이 돌아오면 "설치 가능"으로 보지 않아 `앱 설치` 메뉴가 아예 뜨지 않고
  바로가기만 만들어진다(바로가기는 브라우저 탭이라 주소창이 보인다). 그래서
  `_infra/worker.js` 의 `LIFE_PUBLIC_PATHS` 에 `manifest.json`·아이콘·`styles.css`
  만 열어 두었다 — 드러나는 것은 앱 이름과 아이콘뿐이다.
  매니페스트 링크의 `crossorigin="use-credentials"` 도 함께 필요하다.
- PWA 는 `display: standalone` 이라 주소창이 보이지 않는다. 안드로이드 크롬이 설치
  대상으로 인정하려면 192·512 PNG 아이콘이 필요해 `icon-192.png`·`icon-512.png` 를
  둔다(`_infra/png.mjs` 로 만들었다). 서비스워커는 셸을 캐시해 오프라인에서 열리게만 한다.

## 검증

```bash
node --test _infra/life.test.mjs
npx playwright test _infra/e2e/life.spec.mjs
```

프로덕션에는 `ENABLE_LIFE`, `LIFE_PASSWORD`, `LIFE_SESSION_SECRET` 이 필요하다.
`LIFE` Durable Object 바인딩은 쓰지 않지만, 적용된 마이그레이션을 되돌릴 수 없어
자리만 남아 있다(`_infra/life.js` 주석).
