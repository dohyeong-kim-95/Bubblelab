# 칼로리 (life/kcal)

하루에 먹은 것과 **칼로리·탄단지**를 적는다. 주소는 `life.bubblelab.dev/kcal/`.
LIFE 의 할 일에 `kcal` 을 연결해 두면 두 번 눌러 바로 열린다.

앱 [인아웃](https://www.inout.team/)을 벤치마크했다 — 끼니별 기록, 탄단지 자동 계산,
자주 먹는 것 다시 담기, 몸 정보로 목표 세우기, 그리고 운동으로 태운 칼로리(아웃).

## 답하려는 질문은 "오늘 더 먹어도 되나"

그래서 합계가 아니라 **남은 칼로리**가 제일 크게 나오고, 탄단지는 그램보다 목표를
얼마나 채웠는지가 먼저 보인다. 넘기면 "넘긴 칼로리"로 바뀌고 색이 붙는다.

끼니는 아침·점심·저녁·간식 넷이고, 먹은 것이 없는 끼니도 자리를 지킨다 — 거기 눌러
담는다. 그 아래 **운동**이 같은 모양으로 붙는다. `◀ ▶` 로 지난 날짜를 본다(내일로는
가지 않는다).

## 태운 것

**남은 칼로리 = 목표 + 태운 것 − 먹은 것.** 운동한 만큼 더 먹어도 된다는 뜻이다 —
목표는 섭취 기준이고 소모는 그 여유를 넓힌다.

소모는 **MET(대사당량) × 몸무게 × 시간**으로 센다. 목표를 계산하려고 이미 몸무게를 받아
두었으니, 분당 고정 kcal 표를 두는 것보다 이쪽이 사람에 맞는다 — 같은 30분이라도 무거운
사람이 더 태운다.

```
kcal = MET × 3.5 × 몸무게(kg) ÷ 200 × 분        (Compendium of Physical Activities)
```

지금 있는 것은 **사이클 세 강도**다(`store.js` 의 `EXERCISES`).

| 강도 | MET | 기준 |
| --- | --- | --- |
| 가볍게 | 4 | 여유롭게 · 16km/h 미만 |
| 중간 | 8 | 보통 · 16–19km/h |
| 열심히 | 10 | 빠르게 · 19–22km/h |

강도를 고르고 시간을 적으면 칼로리가 따라온다. **직접 고치면 그때부터 자동 계산을
멈춘다** — 고쳐 둔 값이 시간을 만질 때마다 되돌아가면 놀란다. 다른 운동은 이름과
칼로리를 직접 적으면 된다.

MET 자체가 평균치라 결과도 어림이다. 기계가 잰 값이 있으면 그걸 적는 편이 낫다.

## 목표는 몸 정보에서 나오고, 덮어쓸 수 있다

`⚙` 에서 성별·나이·키·몸무게·활동량을 적으면 계산한다.

- **기초대사량은 Mifflin-St Jeor**(1990) 다. 지금 가장 널리 쓰이고 옛 Harris-Benedict
  보다 현대 체형에서 오차가 작다.
- 활동량을 곱해 하루 소모(TDEE)를 내고, 목표(감량 ×0.8 / 유지 / 증량 ×1.1)를 적용한다.
  **감량이라도 기초대사량 아래로는 내려가지 않는다** — 그 아래는 목표가 아니라 굶는 것이다.
- 탄단지는 식단 프리셋의 열량 비율로 나눈다(일반 50/20/30 · 운동 40/30/30 ·
  고단백 35/35/30 · 저탄고지 10/25/65). 그램 환산은 4·4·9 다.
- 계산이 마음에 안 들면 **직접 적기**를 켜고 숫자를 덮어쓴다. 그 뒤로는 몸무게를 고쳐도
  내가 적은 목표가 지켜진다(다시 계산시키려면 체크를 끈다).

어디까지나 추정이다. 실제 대사량은 사람마다 ±10% 안팎으로 다르다.

## 먹은 것 담기

`＋ 담기` → 이름으로 찾아 **여러 개를 눌러 두고** → 한 번에 담는다. 한 끼는 대개 한
품목이 아니라 몇 가지라, 하나 담고 팝업이 닫히고 다시 여는 것을 반복하게 두지 않는다.

- 줄을 누르면 골라지고 다시 누르면 빠진다(왼쪽 네모가 그 표시다). 찾기를 다시 해도
  눌러 둔 것은 풀리지 않는다 — 이름·회사로 기억한다.
- 여러 개는 **1인분씩** 담긴다. 양이 다르면 담긴 줄을 눌러 고친다.
- 하나만 골랐을 때는 `양·끼니를 정해서 담기` 로 옛 흐름(수량·끼니 정하기)이 그대로 열린다.
- **고른 개수에 따라 자리가 바뀌지 않는다.** 0개·1개·여러 개에서 뼈대는 같고, 할 수 없는
  버튼은 사라지는 대신 흐려진다. 목록 칸의 높이도 결과 수와 상관없이 같다 — 검색할 때마다
  아래 버튼이 오르내리면 누르려던 자리가 매번 달라진다(e2e 가 버튼 좌표를 재어 지킨다).

- **자주 먹는 것을 따로 저장하지 않는다.** 담은 기록에서 뽑는다 — 자주 먹을수록, 최근일수록
  위로 온다. 즐겨찾기를 따로 두면 기록과 어긋나고 관리할 것이 하나 는다.
- 같은 이름이 내 기록과 음식표 양쪽에 있으면 **내 기록만** 보여 준다. 표의 값과 내가
  마지막에 담은 값이 나란히 뜨면 어느 쪽이 내 것인지 알 수 없다.
- 목록에 없으면 `직접 적기` 로 이름·칼로리·탄단지를 적는다. 한 번 적으면 다음부터는
  목록에 남는다.
- 값은 **1회 제공량(단위) 기준**으로 넣고 수량을 곱한다. 담기기 전에 곱해진 값을 보여 준다.
- 담은 것을 누르면 고치거나 지운다.

**끼니 칸은 지금 시각의 것만 펴져 있다.** 아침(04–11시)·점심(11–16시)·저녁(16–22시),
그 밖의 시간은 간식이다(`mealNow`). 네 칸을 다 펴 두면 적을 자리를 매번 찾아 내려가야
한다. 머리줄을 누르면 여닫히고, **접힌 칸에도 몇 개·몇 kcal 인지는 남는다** — 빈 칸처럼
보이면 안 적은 줄 알고 두 번 담게 된다. 여닫은 상태는 저장하지 않는다(화면을 다시 열면
그때 시각의 끼니가 펴진다).

## 음식표(`foods.js`)

리포에 실려 있는 표다. **사람이 채워 넣는다** — 외부 API 를 부르지 않는 화면이라
자동으로 채워지지 않는다. 포장지의 영양성분표를 보고 한 줄씩 는다:

```bash
node _infra/kcal-food.mjs --name "프로틴 드링크 퍼펙트 초코" --brand "랩노쉬" \
  --unit "350ml" --kcal 135 --carb 5 --protein 27 --fat 0.6
node _infra/kcal-food.mjs --remove --name "..." [--brand "..."]     # 오타 정정
```

`--kcal` 을 빼면 탄단지에서 4·4·9 로 되짚는다. `--brand` 를 두는 이유는 같은 이름의 제품이
회사마다 값이 달라서다(검색에도 걸린다). 파일은 이름순으로 다시 쓰이므로 손으로 고치지
말 것 — diff 가 지저분해지고 형식이 어긋난다.

`_infra/kcal.test.mjs` 가 표를 검사한다: 형식, 이름+회사 중복, 그리고 **표기 열량과
탄단지가 크게 어긋나지 않는지**(옮겨 적다 틀린 것을 잡는다. 식이섬유·당알코올 때문에
25% 까지는 벌어질 수 있어 그 안쪽만 통과시킨다).

## 화면에서 지킨 것 두 가지

- **취소·담기는 팝업 위아래 두 곳에 있다.** 키보드가 올라오면 아래쪽 버튼이 가려져
  키보드를 내렸다가 눌러야 했다. 위쪽 것은 제목 줄에 붙어 스크롤을 따라온다.
- **브라우저 검증(`novalidate`)을 끄고 값은 `store.js` 가 다듬는다.** number 입력에
  `step="1"` 을 두었더니 78.5kg 처럼 소수를 넣을 때 submit 이 조용히 막혔고, 그 툴팁은
  폰에서 시트에 가려 보이지 않았다 — "저장이 안 된다" 로만 보인다. 막을 일이 있으면
  화면에 이유를 적는다.

## 만듦새

- 목표 계산·세기·자주 먹는 것·찾기는 `store.js` 순수 함수에만 있다. 화면과 테스트가
  같은 모듈을 쓴다 — 합계를 화면 안에서 따로 더하지 않는다.
- 저장은 localStorage(`bl_kcal_v1`) 하나. **서버로 나가는 것은 없다** — 기기끼리
  동기화되지 않고, 백업은 `/backup/` 이 접두사로 담아 간다.
- 날짜는 `YYYY-MM-DD` 문자열이고 자정 경계는 KST 한 곳(`kstDate`)에서만 다룬다.
- 화면 뼈대는 LIFE 의 `../styles.css` 를 물려받는다. 색은 목표를 넘겼을 때만 쓴다.
  팝업은 폰에서 아래에서 올라오는 시트로 열린다.

```bash
node --test _infra/kcal.test.mjs
npx playwright test _infra/e2e/kcal.spec.mjs
```
