# papers — 매일 아침, 내 문제에 쓸 수 있는 최적화 논문

arXiv 에서 하루치를 골라 **디스코드로 보낸다.** 이 화면은 지난 것을 다시 보는 용도다.
토이가 아니라 개인용 피드라 토이 관례(share.js, 주간 기록)를 쓰지 않는다.
**LIFE 의 도구 하나**로 `life.bubblelab.dev/papers` 에 있다 — 서브도메인을 따로 두지
않고 LIFE 의 비밀번호 게이트를 그대로 물려받는다(`life/CLAUDE.md` 의 도구 관례를
따른다: 색은 `../styles.css` 토큰만 쓰고, 인라인 스크립트·스타일은 CSP 가 막는다).
LIFE 홈에서는 할 일에 도구 이름 `papers` 를 붙이면 열린다.

## 창을 닷새로 잡은 이유

arXiv 는 주말에 쉬고 색인에 하루 남짓 더 걸린다. 2026-08-22(토) 23시 KST 에
재어 보니 **색인된 최신 논문이 08-20** 이었다 — 창이 이틀이면 그날 다이제스트가
통째로 빈다. 닷새면 주말과 색인 지연을 함께 넘고, 이미 보낸 논문은 DO 의 `seen`
집합이 ID 로 거르므로 창이 넓어도 같은 것이 두 번 가지 않는다.

## 왜 이런 모양인가 — 실측이 설계를 정했다

만들기 전에 arXiv API 로 실제 발생량을 셌다(2026-07-01 ~ 08-22, 53일).

| 쿼리 | 53일 | 하루 |
|---|---:|---:|
| `cat:cs.LG` 전체 | 6,559 | 124 |
| `cat:math.OC` 전체 | 1,137 | 21.5 |
| **4개 카테고리 합집합** | 7,804 | **147** |
| **↑ + 키워드 선필터** | 311 | **5.9** |
| `abs:"multi-objective Bayesian optimization"` | 8 | 0.15 |
| BO + `categorical`/`mixed-variable` | 4 | 0.08 |

**관심 교집합(다목적 × 순서형/조합 공간 × 저예산)은 2주에 한 편꼴이다.** 그 조건만
걸면 대부분의 날이 빈다. 반대로 카테고리를 그냥 합치면 하루 147편이라 못 읽는다.
그 사이가 **키워드 선필터를 건 하루 ~6편**이고, 그게 LLM 이 전부 채점하기 좋은 크기다.

그래서 선필터는 **arXiv 쿼리 자체에** 넣고(요청 1회), 채점만 LLM 에 맡긴다.

## 파이프라인

**엣지에는 LLM 이 없다.** 채점도 요약도 집 PC 의 `claude -p`(구독)가 만든다 —
API 키를 하나도 늘리지 않으려는 선택이고, `/논문` 답변과 같은 경로다.

```
집 PC 데몬 (1분마다)                     엣지 (Cloudflare)
─────────────────────                   ─────────────────
"오늘 치 만들까?"          ──────────▶   아침 지났나 · 오늘 것 있나 · 남이 만드는 중인가
                          ◀──────────   만들어라 + 이미 본 arXiv ID
① arXiv API 1회  4개 카테고리 × 키워드 × 최근 5일 → ~30편
② 중복 제거      받아 온 ID 로 거른다 (버전 접미사 제거)
③ 채점 claude 1회  후보 전부를 한 번에 비교 채점 1~10점
④ 요약 claude N회  **고른 것만** — 후보 전부에 붙이면 호출이 예닐곱 배
                          ──────────▶   보관 + 디스코드 발송 (🎯 8점↑ / 🔍 5~7점, 최대 5편)
```

**시각을 보는 쪽이 엣지인 이유**는 "오늘 것을 이미 만들었는지" 아는 쪽이 거기라서다.
판단 기준은 보관본이 아니라 **`done:<날짜>` 표시**다 — 고를 게 없던 날은 보관본이
남지 않아서, 보관본만 보면 데몬이 하루 종일 1분마다 같은 하루치를 다시 만들며
arXiv 를 찌른다(2026-08-23 에 실제로 그랬다).
데몬은 1분마다 도는데 채점·요약은 몇 분씩 걸리므로, 넘겨줄 때 **자리를 찜한다**
(`claim`, 20분). 찜이 없으면 앞 실행이 끝나기 전에 다음 실행이 같은 하루치를 또
만들어 디스코드로 두 번 나간다. 찜은 만료되므로 데몬이 죽어도 영영 막히지 않는다.

**봇 토큰은 엣지에만 둔다** — 발송을 PC 로 내리면 토큰까지 내려야 한다.

- **채점을 한 번에 몰아서** 한다. 편마다 부르면 서로를 못 보고 매겨 순위가 흔들린다.
- **8점 이상이 없는 날은 없다고 말한다.** 빈 봉투도, 아무거나 채운 봉투도 안 보낸다.
- **하나도 못 고른 날은 아예 안 보낸다.** "오늘은 없습니다"를 매일 보내면 그것부터
  안 읽게 된다. 대신 본 논문은 기억해서 내일 다시 채점하지 않는다.

## 요약은 "쓸 수 있나" 관점으로 고정

읽는 목적이 서베이가 아니라 적용이라 항목을 못박았다.

```
한줄 / 아이디어 / 가정 / 예산 / 걸림돌
```

`예산`은 논문이 몇 회 평가로 검증했는지, `걸림돌`은 내 문제에 옮길 때 막힐 지점이다.
초록에 없는 내용은 지어내지 말라고 프롬프트에 박아 두었다.

## 화면 — 날짜별로 접고, 논문마다 메모한다

하루치가 `<details>` 한 덩어리다. **맨 위 하루만 펴 둔다** — 매일 쌓이는 화면이라
전부 펼쳐 두면 오늘 것을 보려고 매번 한참 스크롤하게 된다. 접기·펴기는 브라우저
기본 동작이라 스크립트가 없다(상태를 따로 저장하지 않으므로 새로고침하면 다시
맨 위 하루만 펴진 상태로 돌아온다).

논문마다 **댓글**을 남길 수 있다. 읽고 나서 "이건 800회로는 안 되겠다" 같은 판단을
그 자리에 붙여 두는 용도다. 접힌 날에도 `💬 3` 으로 몇 개인지 보인다.

- **댓글은 서버(DO)에 둔다.** LIFE 의 다른 도구는 브라우저 localStorage 를 쓰지만,
  이건 폰에서 적은 것을 PC 에서도 봐야 한다. 다이제스트가 이미 서버에 있으므로
  저장 경계가 늘어나지도 않는다.
- **다이제스트 안에 끼워 넣지 않는다.** 보관본은 서버가 만든 그대로여야 나중에
  무엇이 요약이고 무엇이 내 메모인지 구분이 된다. 키가 따로다(`comment:<arXiv ID>`).
- **`/_papers/comments` 는 LIFE 세션 쿠키로 막는다.** `/_papers/*` 는 게이트보다
  앞에서 처리되므로 여기서 직접 확인하지 않으면 주소만 알면 남이 읽고 쓸 수 있다.
- 한 논문에 20개까지. 넘으면 오래된 것부터 밀린다.

## 설정

| 키 | 종류 | 설명 |
|---|---|---|
| `ENABLE_PAPERS` | var | fail-closed. 내리려면 `"false"` |
| `DISCORD_WEBHOOK_URL` | secret | 채널 설정 → 연동 → 웹훅에서 만든 URL |
| `DISCORD_BOT_TOKEN` + `DISCORD_CHANNEL_ID` | secret | 웹훅 대신 봇으로 보낼 때 (있으면 이쪽이 우선) |
| `PAPERS_SINK_SECRET` | secret | 집 PC 데몬이 하루치를 올릴 때 쓴다. **ASCII 여야 한다**(HTTP 헤더에 실린다) |
| `PAPERS_PROFILE` | var(선택) | 내 문제 설명. 비우면 코드의 기본값 |

### 웹훅과 봇 — OAuth 는 어느 쪽도 런타임에 안 쓴다

자주 헷갈리는 곳이라 적어 둔다. 디스코드 봇의 초대 링크(`scope=bot`)가 OAuth2 이긴
하지만 공식 문서가 **"server-less and callback-less"** 특수 플로우라고 부르는 것이고,
설치가 끝나면 런타임 인증은 **봇 토큰**이다 — *"bot users have full access to most API
routes without using bearer tokens."* OAuth 인증 코드 플로우가 실제로 필요한 건
**남의** 서버·계정을 대신할 때다(`webhook.incoming` 으로 남이 채널을 고르게 하는 경우 등).
내 서버, 내 채널에 올리는 여기는 해당하지 않는다.

그래서 둘 다 지원하고 env 로 고른다(`createDelivery`):

| | 웹훅 | 봇 토큰 |
|---|---|---|
| 설치 | 채널 설정에서 URL 하나 | 초대 링크 한 번 |
| 런타임 | URL 자체가 자격증명 | `Authorization: Bot <token>` |
| 채널 여러 개 | ❌ | ✅ |
| 메시지 수정·스레드·반응 | 제한적 | ✅ |
| 나중에 슬래시 명령 | 불가 | ✅ 같은 토큰으로 |

봇으로 옮길 때 코드는 그대로 두고 `DISCORD_BOT_TOKEN`·`DISCORD_CHANNEL_ID` 만 넣으면
된다(있으면 웹훅보다 우선한다). 슬래시 명령이 필요해지면 디스코드 HTTP Interactions 를
이 워커에 붙이면 되고, 게이트웨이 없이 Workers 에서 공식 지원된다.

## 일정

`0 22 * * *` UTC = **07:00 KST**. arXiv 신규 공지는 미 동부 자정(13~14시 KST)이라
그날치가 다 모인 뒤이고, 출근 직전에 도착한다.

## 함정

- **arXiv 는 `http://` 로 붙으면 301** 이다. `https://export.arxiv.org` 로 고정했다.
- **개정판(v2, v3)이 다시 올라온다.** ID 에서 버전 접미사를 떼고 비교한다.
- **교차게재 중복.** `math.OC` 와 `cs.LG` 동시 등재가 흔한데, 쿼리를 합집합으로
  한 번만 부르므로 arXiv 가 알아서 한 건으로 준다.
- **디스코드 한도는 전체 합 6,000자가 먼저 걸린다**(임베드 10개·설명 4,096자보다).
  담으면서 세고 넘치면 그 자리에서 멈춘다 — 넘기면 400 으로 통째로 거절당한다.
- 키워드를 넓히면 후보가 급격히 는다(6편 → 147편). 늘릴 때는 건수를 먼저 재본다.

## 전용 채널에서 그냥 대화하기

`DISCORD_CHAT_CHANNEL_ID` 채널에서는 **슬래시 명령 없이 그냥 쓰면 답한다.**
다이제스트가 오는 채널은 읽기 전용으로 두고 질문은 여기서 한다.

듣는 길이 **둘**이고, 켜져 있는 쪽이 답한다.

| | 지연 | 봇 토큰 | 띄울 것 |
|---|---|---|---|
| 폴링 (기본) | 1~2분 | 엣지에만 | 없음 (1분 cron 이 겸한다) |
| 상주 (`gateway.mjs`) | 즉시 | **집 PC 에도** | systemd 유저 서비스 |

**둘 다 답하면 같은 말에 두 번 답한다.** 그래서 상주가 1분마다 "듣고 있다" 를
엣지에 알리고(`chat:alive`), 그게 신선하면 폴링이 비켜선다. 설정을 바꿔 가며
고를 필요가 없고, **PC 를 끄면 저절로 폴링이 이어받는다**(신호가 150초 상하면).

### 상주로 올리기

```bash
echo 'DISCORD_BOT_TOKEN=<토큰>' >> ~/.bubblelab/papers.env
bash _src/papers-sink/install.sh
journalctl --user -u papers-gateway -f     # "준비 완료 — <봇이름> 로 듣는다"
```

- **봇 토큰이 PC 에 있어야 한다.** 게이트웨이는 붙는 쪽이 토큰을 들고 IDENTIFY 를
  보내는 구조라 엣지가 대신 붙어 줄 수 없다. 엣지 것은 **지우지 않는다** —
  다이제스트 발송과 슬래시 명령 등록이 그걸 쓴다. 토큰을 새로 발급하면 양쪽을
  같이 바꾼다(`npx wrangler@4 secret put DISCORD_BOT_TOKEN`).
- 생각하는 동안 "입력 중…" 을 계속 찍는다(디스코드는 10초면 지운다).
- 답하는 데 몇 분이 걸릴 수 있어서 **말을 줄 세워 하나씩** 답한다.
- 끊기는 건 정상이다(디스코드가 주기적으로 op 7 을 보낸다). **RESUME 으로
  이어붙여야** 끊긴 사이의 말을 놓치지 않는다.
- `4004`(토큰 틀림)·`4014`(인텐트 거부)는 다시 붙어도 같은 결과라 프로세스를
  세운다 — 무한 재시도로 로그를 채우지 않는다.

### 공통

- **개발자 포털 → Bot → Message Content Intent** 를 켜야 글 내용이 온다.
  꺼져 있으면 글은 오는데 내용만 빈 채로 와서, 로그에 그렇다고 남긴다.
- **처음 켠 순간에는 밀린 글에 답하지 않는다** — 커서 자리만 잡는다.
- **커서는 답한 뒤에 옮긴다.** 먼저 옮기면 답을 만들다 죽었을 때 그 말이 사라진다.
- 오간 말을 12개까지 기억해서 "그럼 그거 말고는?" 같은 되묻기가 된다. 기억은
  엣지에 있으므로 PC 를 갈아엎어도 대화가 남는다.

`/논문` 슬래시 명령도 그대로 남아 있다.

### 읽기로 한 논문은 글로 남는다

대화에서 "이거 리뷰해줘" 라고 하면 한 편을 붙들고 정리해서 **life/papers 에
쌓는다.** 채널의 대화는 흘러가고 12개까지만 기억되지만 리뷰는 남는다 —
**그냥 물어보는 것과 이 도구가 갈리는 지점이 여기다.**

일곱 항목으로 못박아 둔다: 무엇을 한 논문인가 · 핵심 방법 · 전제와 가정 ·
실험 설계 · 내 문제 적용 · 따라 해볼 것 · 한계와 의심. 다이제스트의 다섯 줄이
"읽을지 말지" 를 정하는 용도라면, 이건 읽기로 한 뒤의 결과물이다.

- **초록만 보고 쓴다는 걸 숨기지 않는다.** 본문을 봐야 아는 것은 "본문의 어디를
  봐야 한다" 고 적게 한다 — 지어낸 확신보다 정확한 모름이 낫다.
- 채널에는 앞 세 항목만 보내고 전문은 화면으로 넘긴다. 긴 글은 디스코드에서
  안 읽힌다.
- 리뷰에도 **댓글을 달 수 있다.** 나중에 다시 읽고 생각이 바뀐 걸 붙여 둔다.
- 저장은 데몬(sink secret)이 하고, 읽기는 LIFE 세션이다. 200편까지 쌓인다.

### 논문 검색은 모델이 아니라 데몬이 돈다

**도구 없이 부르는 `claude` 에게 논문을 물으면 arXiv 번호를 지어낸다** — 기억으로
답하기 때문이다. 그래서 두 걸음으로 나눴다.

```
① claude 에게 "지금 말에 답하려면 논문을 찾아야 하나?" 를 묻는다
   → 찾아야 하면 첫 줄에 SEARCH: <영어 검색어> 만 쓰게 한다
② 데몬이 실제로 arXiv 를 부른다 (기간 제한 없음·관련도순 → 옛날 논문도 나온다)
③ 그 결과만 보여 주고 다시 답하게 한다 — "목록에 없는 번호를 쓰지 말라" 를 못박고
```

도구를 쥐여 주지 않으므로 인젝션 위험이 지금보다 늘지 않는다(초록은 여전히 남이 쓴
텍스트지만, 모델이 할 수 있는 건 읽고 답하는 것뿐이다).

하루치 수집(`fetchCandidates`)과 **다른 함수**(`searchArxiv`)인 이유: 저쪽은 날짜 창 +
키워드 선필터가 핵심이고, 이쪽은 기간 제한이 없고 관련도순이다.

## 슬래시 명령 — `/논문 질문:<질문>`

받아본 다이제스트에 대해 그 자리에서 물어볼 수 있다. 다이제스트와 마찬가지로
**답도 집 PC 의 Claude Code(`claude -p`)가 만든다** — 이미 쓰는 구독에서 차감되므로
LLM API 키가 하나도 늘지 않는다.

```
디스코드 /논문  →  워커가 질문을 DO 에 적어 둠  →  즉시 "물어보는 중…" 표시
집 PC 데몬(1분) →  질문을 가져가 claude -p 로 답  →  원래 메시지를 답으로 교체
```

invest 의 "지금 갱신" 과 같은 구조다 — 엣지가 못 하는 일을 PC 가 가져간다.
거래도 같다: **PC 가 꺼져 있으면 답이 오지 않는다.**

### 왜 게이트웨이가 아니라 HTTP Interactions 인가

디스코드 봇은 보통 상시 웹소켓(게이트웨이)을 물고 있어야 해서 워커에서는 안 된다.
대신 **Interactions Endpoint** 를 쓰면 디스코드가 우리 URL 로 POST 하고 우리가
JSON 으로 답하는 구조가 되어, 요청 단위로만 사는 런타임에서도 봇이 성립한다.
상시 켜 둘 프로세스가 없다 — 오픈클로 같은 자체 호스팅 에이전트와 갈리는 지점이다.

지켜야 하는 세 가지. 하나라도 어기면 디스코드가 엔드포인트를 꺼 버린다:

1. **모든 요청의 Ed25519 서명을 검증하고, 틀리면 401.** 200 으로 답하면 등록 자체가
   거부된다. 워커는 표준 `Ed25519` 를 지원한다(예전 `NODE-ED25519` 는 레거시).
2. **PING(type 1) 에 PONG(type 1).** 엔드포인트 등록 때 이걸로 확인한다.
3. **3초 안에 응답.** LLM 은 더 걸리므로 먼저 `type 5`(생각 중)로 답하고, 실제 답은
   15분 안에 `PATCH /webhooks/{app_id}/{token}/messages/@original` 로 채운다.
   워커는 응답과 함께 죽으므로 **`ctx.waitUntil()`** 로 붙잡아야 한다.

### 설정

| 키 | 용도 |
|---|---|
| `DISCORD_PUBLIC_KEY` | 서명 검증 (개발자 포털 → General Information) |
| `DISCORD_APPLICATION_ID` | 답을 채워 넣을 주소. 엣지·PC 양쪽에 필요 |
| `PAPERS_SINK_SECRET` | PC 데몬이 질문을 가져갈 때의 인증. 양쪽에 같은 값 |
| `DISCORD_BOT_TOKEN` | **명령어 등록에만** 필요 — 엣지에는 안 넣어도 된다 |

`PAPERS_SINK_SECRET` 은 **ASCII 로 만든다.** HTTP 헤더에 실리므로 한글이 들어가면
데몬이 요청을 만들다 죽는다.

```bash
# 집 PC 데몬 — 1분마다 질문을 가져가 답한다
* * * * * cd <리포경로> && set -a && . ~/.bubblelab/papers.env && set +a && <node경로> _src/papers-sink/index.mjs >> ~/.bubblelab/papers.log 2>&1
```

**`CLAUDE_BIN` 에 `claude` 절대경로를 넣는다.** cron 의 PATH 는 `/usr/bin:/bin` 뿐이라
`~/.local/bin/claude` 를 못 찾는다 — node 와 똑같은 함정이고, 질문이 처음 올 때까지
드러나지 않는다(질문이 없으면 claude 를 부르지 않으므로 cron 은 조용히 성공한다).

데몬은 claude 를 부를 때 **stdin 을 닫고**(안 그러면 파이프 입력을 3초 기다렸다가
경고를 낸다) **PATH 에 node 디렉터리를 넣는다**(claude 의 플러그인 훅이 `node` 를
못 찾아 실패 로그를 남긴다 — 답변은 나오지만 로그가 지저분해져 진짜 오류가 묻힌다).

질문이 없으면 엣지에 가벼운 GET 한 번으로 끝난다 — `claude` 를 부르지 않으므로
구독 한도를 축내지 않는다. 한 번에 최대 3개까지만 답한다(폭주 방지).

```bash
# 명령어 등록 (한 번, 그리고 명령어를 바꿀 때마다)
PAPERS_SINK_SECRET=... node _src/discord/register.mjs
```

**봇 토큰은 여기 필요 없다.** 등록은 엣지가 대신 한다(`POST /_discord/commands`,
sink secret 으로 인증) — 토큰은 다이제스트 발송 때문에 어차피 Cloudflare 에 있고,
그걸 로컬로 꺼내면 셸 히스토리에 남는다. 폰만 있어도 되는 이유이기도 하다:
토큰은 Cloudflare 대시보드(Workers & Pages → 워커 → Settings → Variables and
Secrets → Add → Secret)에서 넣으면 터미널이 아예 필요 없다.

개발자 포털의 **Interactions Endpoint URL** 에
`https://life.bubblelab.dev/_discord/interactions` 를 넣는다. 저장 버튼을 누르는
순간 디스코드가 PING 을 쏘므로, **secret 을 먼저 넣고 배포한 뒤** 등록해야 한다.

### 안전

- 엔드포인트에 게이트가 없다. 게이트 대신 **서명이 유일한 관문**이라, 서명 검증을
  느슨하게 만드는 변경은 곧 아무나 명령을 흉내 낼 수 있다는 뜻이다.
- 질문은 500자에서 자른다. 답변은 1,400자에서 자른다(임베드 한도 4,096 보다 앞서
  읽기 힘들어진다).
- **`claude -p` 를 도구 없이(`--allowed-tools ""`) 부른다.** 프롬프트에 arXiv 초록이
  그대로 들어가는데 그건 남이 쓴 검증되지 않은 텍스트다. 도구가 없으면 초록에 지시를
  심어 둬도 읽고 답하는 것 말고 할 수 있는 게 없다 — 오픈클로를 걱정했던 지점이
  여기서는 사라진다.
- **`/_papers/asks` 는 sink secret 으로 막혀 있다.** 질문 원문과 다이제스트가 오간다.
- **`/_papers/digest/*` 도 sink secret 뒤에 있다.** 열려 있으면 아무나 남의 채널로
  발송을 시킬 수 있다 — `PUBLIC_PATHS` 로 읽기 전용 경로만 통과시킨다.
