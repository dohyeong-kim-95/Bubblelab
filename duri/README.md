# duri — 둘이서 쓰는 대화·사진 백업 (E2E)

상태: **개발 중**. duri.bubblelab.dev, 자체 비밀번호 게이트 뒤 비공개.

두 사람이 주고받은 대화와 사진이 **각자의 컴퓨터 디스크에 저절로 쌓이는** 기록
시스템. 대화·사진 백업이 목적이라 bubblelab의 "토이 · 외부 서비스 금지" 원칙과
결이 다르므로, 랜딩·풀다운에 노출되지 않는 비공개 **전용 서브도메인**
`duri.bubblelab.dev`에 둔다(`_infra/build.mjs`의 `CONFIDENTIAL_SUBDOMAINS`).

원래 `work.bubblelab.dev/duri`(work 게이트 하위 경로)였으나, 앱화 후 work 홈
경유·주소 재입력이 번거로워 전용 서브도메인으로 승격했다. DuriDO는 호스트와
무관한 단일 인스턴스(`idFromName("main")`)라 승격으로 데이터가 옮겨가지 않는다.
암호 문구는 오리진별 localStorage에 있으므로 새 서브도메인에서 한 번 다시 입력한다.

## 게이트 (bl_duri, 1년 세션)

세션 쿠키는 **별도(`bl_duri`)이고 1년**이라, 설치형 앱은 최초 1회만 로그인하면
사실상 다시 묻지 않는다. 이 게이트는 E2E 암호 문구와 무관하다(문구는 앱 안에서
따로 받는다). 라우팅·게이트는 `_infra/worker.js`의 `handleDuriGate`·`duriPassword`.

- **비밀번호는 `DURI_PASSWORD` secret**을 쓴다. 없으면 `WORK_PASSWORD`로 폴백한다
  (설정 전에도 안 끊기게). `DURI_PASSWORD`를 설정하면 duri 접속 비번이 work과
  **완전히 독립**되고(work 로그인은 영향 없음), 파생 키가 바뀌어 **기존 bl_duri
  세션·싱크토큰(`DURI_SINK_SECRET` 미설정 시)은 무효화**된다 — 비번만 갈아도
  "접속 새로 시작"이 된다. 두 사람은 새 비번으로 다시 로그인한다.

## 방 초기화 (새로 시작)

앱 헤더의 **방초기화** 버튼 → `POST /_duri/reset`(소유자=`bl_duri` 세션만, 싱크
토큰으로는 불가). DuriDO가 서버 버퍼 전체 + 참조/고아 사진(R2) + 공유 캘린더
전체(`cal:*`)를 비우고 접속자에게
`reset`을 브로드캐스트해 양쪽 기기가 로컬 캐시를 지우고 재시작한다. **seq 카운터는
되감지 않고**(초기화 중 오프라인이던 기기의 커서 문제 방지) `ackSeq`를 `head`로
올려 "전부 소비됨"으로 만든다. **각자 PC 싱크 아카이브(원본)는 서버가 손대지
못하므로 그대로 남는다** — 정말로 지우려면 각 PC의 `DuriStorage/`를 직접 삭제.

## 구조 — 엣지는 중계소, 원본은 내 PC

- **Cloudflare(엣지) = 실시간 중계 + 임시 버퍼.** 영구 저장고가 아니다. 워커·DO·R2는
  전부 **E2E 암호블롭**만 다루므로 평문·키·신원을 알지 못한다.
- **데스크톱 싱크 = 진실의 원천.** 사용자 PC에서 상주하며 새 항목을 받아 로컬
  디스크에 기록하고 서버에 ack 한다 → 서버는 버퍼·R2에서 그 항목을 폐기한다.
  소스는 배포에서 제외되는 `_src/duri-sink/`(의존성 0, Node 22+). apk는 다음 단계.

## 앱화 (PWA)

홈 화면에 설치해 앱처럼 쓸 수 있다. `manifest.json` + `icon.svg`와 `<head>`의
apple/mobile 메타만으로 구성한 **최소 설치형 PWA**다. 최신 Chrome/Android는
매니페스트만으로 설치되고, iOS는 "홈 화면에 추가"로 담는다. 매니페스트는 duri
게이트 뒤라 `crossorigin="use-credentials"`로 받는다. `start_url`·`scope`는
서브도메인 루트(`/`)라 앱을 열면 곧바로 duri 홈이 뜬다(work 홈 경유 없음).

- **서비스워커(`sw.js`)는 푸시 알림 표시 전용 — 오프라인 셸 캐싱은 아직 없음.**
  `fetch` 핸들러가 없어 게이트/`no-store` 헤더와 부딪힐 일이 없다(캐시 전략은
  여전히 다음 단계). `install`/`activate`/`push`/`notificationclick`만 처리한다.
- 아이콘 PNG(iOS `apple-touch-icon` 고해상도용)는 지금 SVG 하나로 갈음한다.

## E2E 암호화 (공유 패스프레이즈)

- 두 사람이 **같은 암호 문구**를 각자 최초 1회 입력 → PBKDF2(210k, SHA-256)로
  AES-GCM 256 키 파생. 문구·키는 기기를 떠나지 않는다.
- 메시지·사진·발신자 이름·캡션까지 전부 암호화되어 오간다. 서버엔 `{ iv, ct }`
  불투명 값뿐. 문구가 다르면 상대 메시지는 "복호화 불가"로 표시된다.
- 문구 입력칸(`#pass`)은 `type="password"`가 아니라 `type="text"` +
  `-webkit-text-security: disc`로 화면엔 점만 보이게 가린다 — 일부 한국어
  키보드 앱이 실제 password 필드를 "보안 키보드"로 인식해 영문 전환 키
  자체를 빼버리는 문제가 있어서다.

## 공유 캘린더

채팅과 함께 쓰는 둘만의 캘린더. 화면은 **[채팅 | 캘린더] 두 장**이고 좌우
스와이프로 넘긴다 — 채팅에서 **왼쪽으로** 밀면 캘린더(오른쪽 화면 밖에서 끌려
들어온다), 캘린더에서 **오른쪽으로** 밀면 채팅. 헤더의 📅·‹ 버튼도 같은 일을 한다.
드래그 중엔 손끝을 그대로 따라가고(실시간 추적), 손을 뗀 순간 남은 진행률로
스냅한다 — 탭을 당겨오는 느낌. 열 때는 30% 이상 끌어야 하지만, 돌아갈 때(캘린더→
채팅)는 15%만 끌어도 닫힌다(뒤로가기는 가볍게).

- **월간**: 날짜 아래에 최대 2개 제목을 작게 미리보기하고(넘치면 `+N`), 고른
  날의 일정은 격자 아래 패널에서 전체를 읽는다. 날짜를 **한 번** 누르면 선택만
  바뀌고 패널의 **＋ 일정**으로 추가하며, 같은 날짜를 400ms 안에 **두 번**
  누르면(더블클릭/더블탭) 그 날짜의 일정 추가 다이얼로그가 바로 열린다(네이티브
  dblclick 대신 클릭 타이밍으로 직접 판정 — 모바일 PWA 터치에서 더 안정적).
- **주간**: 하루 한 장의 카드 목록(어젠다). 카드를 누르면 그 날 일정 추가.
- **월간↔주간 전환**: 세그먼트 버튼(월/주) 외에, 격자 위에서 **아래로 스와이프하면
  주간, 위로 스와이프하면 월간**으로 바뀐다(구글 캘린더 제스처 벤치마킹). 좌우
  스와이프(채팅↔캘린더)와 방향 우세로 서로 간섭하지 않는다.
- **월 이동**: 세로 스와이프가 월/주 전환에 이미 쓰이므로, 월간 화면 맨 아래에
  **‹ 저번달 / 다음달 ›** 버튼을 따로 둔다(엄지로 누르기 쉬운 위치). 헤더의
  ◀ ▶ 도 같은 동작.
- 일정은 **종일**이거나 **시작·끝 시간**을 갖는다. 정렬은 종일 먼저, 그다음 시작시간.
- 분류는 `내 일정`·`공통` 둘뿐이다. 상대가 만든 일정(`owner` ≠ 내 이름)은 자동으로
  "상대" 색이 된다. 색 세 개는 🎨에서 **기기별로** 바꾼다(색은 동기화되지 않는다).
- "오늘" 버튼은 오늘이 화면 밖에 있을 때만 나타난다.
- **일정 색**: 종일 일정은 색을 꽉 채운 알약 + 흰 글자, 시간 일정은 배경 없이
  색점 + 지금까지와 같은 글자색(배경과 비슷하게 옅다). 글자는 굵게(800) + 자간을
  좁혀 좁은 칩 안에 최대한 많은 글자가 보이게 했다. 기본 색 세 개(mine/theirs/
  shared)도 파스텔톤(더스티 로즈·블루·세이지)으로 낮췄다 — 다만 흰 글자가
  읽혀야 해서 아주 옅은 파스텔까지는 못 가고 채도만 낮춘 중간 톤이다(대비비
  4:1 안팎으로 확인).
- **월간 뷰의 일정은 하루짜리든 여러 날이든 같은 위계(같은 줄)에 함께 놓인다**
  (구글 캘린더 벤치마킹) — 하루짜리는 자기 칸 하나만큼, 여러 날 일정은 그만큼
  넓게 막대를 차지하며 같은 레인 배치 규칙을 공유한다. 겹치는 게 있으면 자동으로
  다음 레인에 쌓고(2인용이라 자주 겹치진 않아 단순한 그리디 배치로 충분), 레인이
  3줄을 넘으면 그 아래는 요일별 "+N"으로 접는다. 여러 날 일정은 같은 주
  안에서는 제목이 한 번만 보이고 주가 바뀌면 그 주에서 다시 한 번(반복 일정은
  회차마다 그 날짜에 하루짜리로 따로 그려서 "이 날짜만 삭제"가 회차를 구분할
  수 있게 한다). 막대가 날짜 숫자보다 위로 올라오지 않도록, 한 주는 [날짜 숫자
  줄 → 일정 막대 레인 → 빈 탭 영역] 순서로 그린다(`.cal-week-dates` →
  `.cal-week-bars` → `.cal-week-days`).
- **표식(스티커/이모지)**: **일정이 아니라 날짜 자체**에 붙는다 — 글로 남기기
  애매한 걸 이모지 하나로 표시할 때 쓴다. day 패널 헤더의 별(⭐) 버튼을
  누르면 8칸 팝업이 근처에 뜬다 — 첫 칸은 항상 "✕ 지우기", 나머지 7칸은
  미리 골라 둔 이모지(`MARKER_EMOJIS`)라 그중 하나를 누르면 그 날짜에
  담긴다(직접 타이핑하지 않음). 일정과 분리돼 있어서 일정을 하나도 안
  만들어도 표식만 남길 수 있고, 월간 뷰의 일정 막대(레인)를 전혀 차지하지
  않는다 — 항상 날짜 숫자 옆 배지(.8rem 이모지)로만 보여서 다른 일정들과
  자리다툼이 없다. 구현은 같은 `cal:<id>` 저장소를 재사용하되 id를 날짜에서
  결정적으로 만들어(`mk20260810` 식) 날짜당 하나만 존재하게 하고
  `kind:"marker"` 로 표시해 일반 일정 목록·반복 계산에서 제외한다
  (같은 LWW·방초기화·오프라인 큐를 그대로 물려받는다).
- **한국 공휴일**은 🇰🇷 표시로 자동으로 뜬다(서버에 저장하지 않는 가상 이벤트라
  양쪽 기기가 각자 계산 — 공개 정보라 굳이 암호화·동기화할 필요가 없다). 색은
  내꺼/상대꺼/공유와 겹치지 않는 별도의 빨강(`calColors.holiday`, 요일 헤더의
  일요일 빨강 `--sun`과 같은 톤)이라 실제 공유 일정과 한눈에 구분된다. 신정·삼일절·노동절·어린이날·현충일·제헌절·광복절·개천절·한글날·
  크리스마스 같은 **고정일은 연도 상관없이 대체공휴일까지 계산**해서 나오지만,
  **설날·추석·부처님오신날(음력)은 변환 로직이 없어 확인해 둔 2026·2027년치만**
  들어 있다(그 뒤 연도가 필요해지면 `LUNAR_HOLIDAYS`에 추가). 설날·추석은 여러
  날 공휴일이라 위 막대 표시를 그대로 탄다. 탭하면 수정 다이얼로그 대신 이름만
  토스트로 뜬다 — 실제 일정이 아니라 고치거나 지울 수 없다.
- 일정 추가 다이얼로그는 제목 입력창에 포커스가 가면 키보드가 뜨는데, 이때
  `visualViewport` 로 실측한 키보드 높이(`--kb-live`)만큼 하단 여백을 늘려
  **키보드 위 보이는 영역 안에서** 가운데 정렬한다(전체 화면 기준으로 정렬하면
  키보드에 가려질 수 있어서). 카드가 그 영역보다 크면 카드 안에서 스크롤.
- **다이얼로그** (네이티브 캘린더 앱 벤치마킹): 제목은 테두리 없는 큰 글씨
  입력(placeholder "제목"). 시작일·종료일은 화살표(→/←) + 전체 날짜 텍스트
  행으로 보여주고, 행 전체가 탭 영역이라 어디를 눌러도 네이티브 날짜 피커가
  뜬다(둘 다 직접 편집 가능 — 시작일을 나중 날짜로 옮기면 종료일도 못 미치지
  않게 따라온다). "종일"은 iOS식 on/off 토글이고, 켜져 있으면 시작·끝 시간
  입력은 아예 감춘다. "반복"은 기본 접힌 칩(🔁 반복)이라 눌러야 주기·종료
  옵션이 펼쳐진다 — 대부분 일정은 반복이 아니라서 폼을 가볍게 유지한다.
- **여러 날에 걸친 일정**: 종일 + 종료일을 시작일보다 뒤로 잡으면 그 범위의 모든
  날짜에 나타난다(각 날짜에 같은 제목이 반복 표시되는 방식 — 격자 칸을
  가로지르는 띠는 아니다).
- **반복 일정**: 반복 토글을 켜면 **주기**(매일/매주/매월/매년) + **종료**
  방식(계속/날짜까지/횟수만큼, 예: "5번")을 고른다. 회차마다 따로 저장하지
  않고 **시리즈 하나(시작일 + 규칙)로 계산**해서 매번 그려진다. 매월 반복은
  시작일이 31일이면 31일이 없는 달은 자연히 건너뛴다(예: 1/31 매월 → 2월엔
  없고 3/31에 다시). **여러 날 종료일과 반복은 함께 쓸 수 없다**(반복 설정 시
  종료일 무시, 다이얼로그에 안내 문구).
- **반복 일정 삭제**: **이 날짜만 삭제**(그 회차만 `recur.exclude` 목록에 넣어
  건너뛰고 나머지 시리즈는 유지) / **전체 삭제**(시리즈 전체를 지운다) 둘 중
  선택한다. 제목·시간 등 다른 값을 고쳐 저장하는 일반 편집은 여전히 시리즈
  전체에 적용된다 — "이 회차만 제목 바꾸기" 같은 예외 편집은 없다.

### 저장·동기화 (채팅 버퍼와 다르다)

채팅·사진은 싱크가 ack 하면 서버에서 사라지는 **버퍼**지만, 캘린더는 계속 남아야
하므로 DO 스토리지의 **지속 상태**로 둔다. 이벤트 하나가 키 하나(`cal:<id>`)이고
값은 E2E 암호블롭 `{iv, ct}` + `rev`(수정시각). 양쪽이 같은 일정을 고치면 **rev
큰 쪽이 이긴다**(last-write-wins). 삭제는 툼스톤(`deleted:true`)으로 전파된다.
접속하면 `cal-hello` → `cal-state`로 전체를 받고, 이후 변경은 `cal-put`/`cal-del`로
중계된다. 오프라인 중의 변경은 클라이언트 `calOutbox`에 쌓여 재접속 때 보낸다.
이 기기 사본은 `localStorage["duri:cal"]`(새로고침 시 즉시 그리기용).

### 아직 안 된 것 (알고 쓰는 한계)

- **데스크톱 싱크가 캘린더를 백업하지 않는다.** 싱크는 `msg`/`photo` 항목만 디스크에
  쓰므로 캘린더의 유일한 원본은 지금 엣지(DO)다 — "엣지는 중계소, 원본은 내 PC"
  원칙 밖이고, 방초기화하면 일정도 함께 사라진다.
- **툼스톤이 정리되지 않는다.** 삭제 표시가 영구히 남고 `MAX_CAL_EVENTS`(2000)
  카운트에 포함된다 → 만들고 지우기를 2000번 반복하면 새 일정이 조용히 거부된다.
- 반복 일정은 **회차별 예외가 없다**(하나 고치면/지우면 시리즈 전체). 알림은 없다.

### 채팅에서 "/일정" 명령으로 추가

채팅 입력창에 `/일정 제목`을 타이핑하면 입력창 위에 **📅 일정 칩**이 뜬다(그대로
Enter를 쳐도 칩을 누른 것과 같다). 누르면 이번달+다음달을 보여주는 미니 달력이
열리고, **아고다식으로 시작일을 한 번, 종료일을 한 번 더 탭**하면(같은 날을
두 번 탭하면 하루짜리) 그 자리에서 바로 종일 일정이 추가된다. **시간 지정·반복은
지원하지 않는다** — 텍스트로 "이 반복 일정 지워줘" 같은 걸 안전하게 특정하기
어렵고 잘못 지우면 공유 캘린더라 되돌리기도 번거로워서, 명령은 의도적으로
추가 전용+ 종일/여러 날만 지원한다. 시간·반복이 필요하면 캘린더 탭에서 편집.

성공하면 상대도 볼 수 있게 채팅에 **오픈카톡 입장 메시지 같은 시스템 알림**
("📅 "test" 일정 추가됨 (7/26 (일))")을 하나 남긴다 — 일반 말풍선과 안 헷갈리게
가운데 정렬 알약으로 그린다. 이 알림도 다른 메시지와 똑같이 **진짜로 E2E
암호화되어 상대·PC 백업에 남는다**(`sys` 플래그로 렌더링만 다르게 할 뿐, 프로토콜
상으로는 평범한 `msg` 항목). 새 일정은 기본 **공통**(양쪽 다 보임)으로 만들어진다
— 색·소유자를 바꾸려면 캘린더 탭에서 편집.

## 새 메시지 푸시 알림 (기본 꺼짐)

설정(⚙️) 메뉴의 **🔔 푸시 알림** 토글로 기기별로 켠다(기본 꺼짐). 켜면 상대가
메시지·사진·스티커를 보낼 때 이 기기로 브라우저 알림이 온다(카톡 벤치마킹).
소리·진동은 따로 켜고 끌 수 없다 — 웹 푸시 API엔 커스텀 사운드가 아예 없고
진동 패턴도 iOS Safari는 지원하지 않아, 켜고 끄는 옵션 자체가 플랫폼마다
다르게 동작해 혼란만 커질 것 같아 뺐다(OS 기본 동작을 그대로 따른다).

- **서버는 알림을 보낼 때도 평문을 모른다.** 푸시 페이로드엔 채팅과 똑같은
  암호블롭(`{iv,ct}` 또는 사진의 `{metaIv,metaCt}`)만 실어 보내고, **`duri/sw.js`가
  이 기기 안에서 그 자리에 복호화**해서 보낸 사람 이름과 내용을 알림에 채운다.
  텍스트는 그대로, 사진은 "사진", 스티커는 "(이모티콘)"으로 뜬다(캡션·스티커
  이미지 자체는 안 보여줌). 브라우저 푸시 중계 서버(FCM 등)는 암호문만 스쳐
  간다 — 평문이 서버·중계 어디에도 남지 않는다.
- **복호화 키는 IndexedDB "meta" 스토어**에 있다(로그인 시 저장). `localStorage`는
  서비스워커에서 못 읽어서 별도로 둔 것 — 신뢰 수준은 기존 localStorage 저장과
  동일(둘 다 "이 기기에만, 서버로는 안 감"). 문구를 다시 입력하면 여기도 함께
  지워진다.
- **내가 보낸 메시지는 내 기기에 알리지 않는다.** 서버는 발신자를 구분하지 못해
  구독된 모든 기기에 그대로 브로드캐스트하므로, 복호화한 뒤 메시지에 실린
  `name`을 같은 "meta" 스토어에 저장된 내 이름과 비교해 일치하면 알림을 띄우지
  않는다(`duri/sw.js`의 `buildNotification`). 둘이 같은 이름을 쓰면 서로 구분이
  안 돼 이 필터가 무의미해진다 — 채팅 말풍선 좌우 정렬도 같은 이름 비교를 쓰므로
  기존 제약과 동일하다.
- 페이로드가 너무 크면(긴 텍스트 등, 3KB 초과) 내용 없이 "새 메시지가 도착했어요"
  일반 알림으로 대체된다(`DuriDO.buildPushPayload`).
- **이 기기에서 앱 화면을 이미 보고 있으면(포커스 중) 알림을 띄우지 않는다** —
  `sw.js`가 `clients.matchAll()`로 포커스된/보이는 창이 있는지 먼저 확인하고,
  있으면 조용히 넘어간다(웹소켓으로 화면에 이미 뜨는데 알림까지 겹칠 필요가
  없다). 백그라운드에 있거나 앱을 안 열어 둔 기기에만 뜬다.
- 구독은 `sink`(데스크톱 데몬)가 아니라 **브라우저(peer)만** 가능하고, 기기당
  최대 8개까지(두 사람 × 기기 몇 대). 방 초기화는 구독을 건드리지 않는다.
- VAPID 키는 새로 만들지 않고 리포에 **이미 있는 걸 재사용**한다(`util/fortune`·
  `podcast`와 공유, `wrangler.jsonc`의 `VAPID_PUBLIC_KEY` + `VAPID_PRIVATE_KEY` secret).

## 서버 구성 (bubblelab 리포 안에서 자립)

- `_infra/duri.js` — `DuriDO`: 릴레이 + 버퍼(ack 시 폐기) + 사진 R2 임시 보관
  + 공유 캘린더 지속 상태(`cal:<id>`, LWW) + 웹 푸시 구독(`push:<hash>`,
  `_infra/webpush.js` 재사용, VAPID는 fortune·podcast와 공유).
- `_infra/worker.js` — `handleDuriGate`(서브도메인 게이트), `/_duri`(WS 중계),
  `/_duri/photo`(업로드/다운로드), `/_duri/push`(GET 공개키 · POST/DELETE 구독,
  peer 전용), `/_duri/sink-token`(소유자 발급), `/_duri/reset`(소유자 방 초기화).
  인증: duri 게이트 세션(`bl_duri`, 브라우저) 또는 싱크 토큰(데몬). 비밀번호는
  `DURI_PASSWORD`(없으면 `WORK_PASSWORD` 폴백).
- `duri/sw.js` — 푸시 알림 표시 전용 서비스워커(캐싱 없음). 페이로드 복호화는
  이 파일 안에서 직접(`index.html`의 `deriveKey`/`decryptJson`과 로직 동일해야 함).
- `wrangler.jsonc` — `DURI` DO 바인딩·마이그v10, `DURI_BUCKET`(R2), `ENABLE_DURI` var.

## 켜는 법 (fail-closed)

`ENABLE_DURI`는 기본 `false`. 켜기 전에:

```bash
npx wrangler@4 r2 bucket create bubblelab-duri
npx wrangler@4 secret put DURI_PASSWORD      # duri 전용 게이트 비번(권장). 없으면 WORK_PASSWORD 폴백
npx wrangler@4 secret put DURI_SINK_SECRET   # 선택: 싱크 토큰 전용 서명키(비번 갈아도 토큰 유지)
# wrangler.jsonc 의 ENABLE_DURI 를 "true" 로 바꾼 뒤 배포
```

버킷·비밀번호(`DURI_PASSWORD`|`WORK_PASSWORD`)가 없으면 `/_duri`는 503으로 닫힌다.
비번을 갈면서도 데스크톱 싱크를 안 끊으려면 `DURI_SINK_SECRET`을 미리 걸어 둔다.
