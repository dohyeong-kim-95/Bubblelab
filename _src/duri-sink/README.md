# Duri 데스크톱 싱크

내 컴퓨터에서 상주하며 Duri 대화·사진을 **로컬 디스크에 저절로 보존**하는 데몬.
"엣지는 중계소, 원본은 내 PC"에서 **원본** 쪽이다. 리포의 `_src/`(배포 제외)
아래 소스이며, 이 폴더를 각자 PC로 복사해 실행한다.

의존성 없음 (전역 `WebSocket`·`crypto`만 사용). **Node 22+** 면 그대로 되고,
**Node 20.10~21** 이면 `--experimental-websocket` 플래그가 필요하다 —
`install.sh` 가 알아서 판별해 서비스 등록에도 붙여 준다.

## 하는 일

1. `/_duri` 에 **싱크 토큰**으로 WebSocket 접속, 마지막 커서 이후 항목을 받는다.
2. **공유 패스프레이즈**로 E2E 복호화 → `DuriStorage/` 에 기록.
3. 디스크에 확실히 쓴 뒤에만 `ack` → 서버가 버퍼·R2에서 그 항목을 폐기.

서버·R2는 암호블롭만 갖고 있어서, 패스프레이즈를 아는 이 데몬만 평문을 만든다.

### 막히지 않기 위한 두 가지 규칙

**① 서버에 없는 seq 는 건너뛴다.** 서버는 자기가 아직 들고 있는 것(ackSeq 이후)만
보내고, 중간에 지워진 사진(`del`)도 번호에 구멍을 남긴다. 예전엔 `cursor+1` 이
올 때까지 3초마다 무한히 기다려서, **ackSeq>0 인 방에 새 싱크를 처음 붙이면 한
건도 저장하지 못한 채 영영 멈췄다**(실제로 그랬다 — 732건이 통째로 막혀 있었다).
지금은 백필이 끝난 뒤(`backfill-done`)라면 빈 번호를 기다리지 않고 넘어간다.

**② 안 풀리는 항목은 격리하고 지나간다.** 복호화 실패 한 건 때문에 그 뒤 전부가
막히면 안 된다(실제로 731건이 딱 한 건에 막혔다). 암호블롭을 그대로
`undecryptable/<seq>.json` 에 남기고(사진은 `.img.enc` 까지 받아 둔다) 커서를
전진시킨다 — 원문을 못 읽어도 원본을 잃지는 않고, 나중에 옛 문구를 알면 풀 수 있다.
다만 **연속 10건**이 실패하면 문구 자체가 틀린 것이므로 그때는 중단한다(전부
격리한 채 ack 해서 서버에서 지워 버리는 게 최악이다).

대화(`msg`)·사진(`photo`)에 더해 **공유 캘린더(`cal:*`)도 백업한다**.

## 저장 구조

```
DuriStorage/
  timeline/2026/2026-07/
    metadata.json     # 정본: 그 달 로그 배열(복호화된 텍스트·사진 메타)
    messages.md       # 사람용 대화록 (metadata에서 재생성되는 View)
    photos/
      2026-07-20T14-45-33_000000000042.png   # 복호화된 원본 사진
  calendar/
    events.json       # 정본: 일정·표식·색설정 전체(툼스톤 포함)
    calendar.md       # 사람용 일정표 (events.json에서 재생성되는 View)
  undecryptable/      # 지금 문구로 안 풀리는 항목의 암호블롭 원본(아래 규칙 ②)
  .duri-cursor        # 마지막으로 보존한 seq (재시작 시 이어받기)
```

### 캘린더는 대화와 규칙이 다르다

캘린더는 버퍼가 아니라 **서버의 지속 상태**라 ack 이 없고, 접속할 때마다
`cal-state` 로 전체가 온다. 그래서 받은 걸로 **덮어쓰지 않고 병합**한다 —
같은 id 는 `rev` 가 큰 쪽(웹앱·서버와 같은 LWW), **서버에 없는 항목은 그대로
남긴다**. 방초기화로 서버가 비워진 뒤 빈 `cal-state` 가 왔을 때 통째로 쓰면
백업까지 날아가기 때문이다 — 그 상황이야말로 백업이 존재하는 이유다.

캘린더 저장이 실패해도 대화·사진 보존은 멈추지 않는다(커서와 분리). 단
복호화 실패는 문구 불일치이므로 대화와 똑같이 즉시 중단한다.

로그 항목은 `type` 으로 갈린다: `message`(텍스트, `sys:true` 면 시스템 알림) ·
`photo` · `sticker`(어떤 팩 몇 번인지) · `location`(`/여기` 로 남긴 좌표).
사진 로그에는 원본 파일명(`photo.original`)·형식·크기·SHA-256(전송 전 해시와
대조한 `hashOk`)이 들어가고, 촬영 위치가 있으면 `loc` 으로 남는다 — 백업만으로
지도를 되살릴 수 있게.

**사진 확장자는 저장할 때 실제 바이트(매직바이트)로 판별한다.** 메타에는 확장자가
없어서 예전 코드는 무엇을 받든 `.jpg` 로 저장했다(아이폰의 HEIC 도 마찬가지였다).
정체를 모르는 바이트는 `.jpg` 라고 우기지 않고 `.bin` 으로 둔다.

## 설치 (한 줄)

```bash
bash install.sh
```

설정이 비어 있으면 파일만 만들어 두고 멈춘다. 앱에서 **⚙️ → 💾 PC 백업 설정 →
🔑 싱크 토큰 발급**으로 나오는 JSON 을 `duri-sink.config.json` 에 붙여넣고
`passphrase` 만 손으로 채운 뒤, 다시 실행하면 systemd 유저 서비스로 등록·기동한다
(`loginctl enable-linger` 까지 — 로그아웃해도 계속 돈다).

- **token**: 앱의 발급 버튼이 `POST /_duri/sink-token` 을 대신 호출해 준다.
  (예전엔 개발자도구에서 `bl_duri` 쿠키를 복사해 curl 을 쳐야 했다 — 그 마찰
  때문에 정작 원본이 아무 데도 안 쌓이고 있었다.)
- **passphrase**: 웹앱에 입력한 것과 **똑같이**. 서버로 전송되지 않고, 앱도 문구를
  갖고 있지 않아서(키 객체만 남긴다) 자동으로 채워 줄 수 없다.
- 설정·데이터는 `.gitignore` 로 커밋되지 않는다. env
  `DURI_URL`/`DURI_TOKEN`/`DURI_PASSPHRASE`/`DURI_DIR` 로도 줄 수 있다.

확인:

```bash
systemctl --user status duri-sink      # 살아 있는지
journalctl --user -u duri-sink -f      # 무엇을 받고 있는지
```

**macOS** 는 `~/Library/LaunchAgents` 에 launchd plist(`RunAtLoad`·`KeepAlive` true),
**Windows** 는 작업 스케줄러 "로그온할 때" 트리거로 등록한다 — `install.sh` 는
systemd 가 없으면 설치까지만 하고 이 안내를 띄운다.

## 일정 비서 "당이" (선택, 기본 꺼짐)

채팅에 **`@당이 …`**(줄여서 **`@당 …`**)라고 쓰면 이 데몬이 **PC 안의 로컬 모델(llama.cpp 또는 Ollama)** 로
읽어 공유 캘린더를 고치고 채팅으로 답한다(`assistant.mjs`). 데몬이 이미 복호화한 메시지를
쓰고 결과도 같은 패스프레이즈로 암호화해 보내므로 **E2E 는 그대로**다 — 서버는 여전히
암호블롭만 본다. 그래서 **PC가 켜져 있고 데몬이 돌 때만** 된다.

```
@당이 토요일 10시 르파비스 임장 넣어줘     → 바로 추가 + "📅 … 일정 추가됨"
@당 이번 주 일정                         → 목록으로 답
@당이 임장 일요일로 옮겨줘 / 출장 지워줘   → 되묻는다 → "@당이 응" 이면 실행, "@당이 취소"
@당 안녕 / 저녁 뭐 먹지?                  → 잡담은 말 말투로 짧게 답한다(op "chat")
@당 오늘 러닝 5km 했어 / 어제 운동 취소     → 말한 사람의 💪 운동 인증 체크·취소(op "fit"/"unfit")
@당 이번 달 운동 몇 번? / 이번주 운동 요약  → 둘 다 몇 번·언제·무슨 운동(op "fitlist", month 또는 week)
@당 우리 성수동 카페 이름 뭐였지? / 어제 무슨 얘기 했지?  → 백업에서 찾아 답한다(op "recall")
@당 제주에서 찍은 사진 보여줘 / 지난달 사진  → 백업에서 골라 채팅에 사진을 띄운다(op "photos")
```

- **기억(recall)은 이 PC 백업(`DuriStorage/timeline/*/*/metadata.json`)을 읽기만 한다**(`archive.mjs` —
  쓰기 API 가 없고, 테스트가 소스에 쓰기 함수가 없는지 검사한다). 모델은 1단계에서 찾을 낱말·기간만
  고르고, 코드가 맞는 줄 + 앞뒤 한 줄(최대 14건)을 찾아 2단계에서 **그 줄만 근거로** 답하게 한다.
  기록에 없으면 모른다고 한다. 당이 자신의 답과 `@당` 명령은 근거에서 뺀다. 데몬 로그엔 대화 내용
  대신 "기억 N줄·일정 n·버킷 n 읽고 답함" 만 남긴다.
- **기억엔 대화 말고 캘린더에 남은 것도 들어간다**(`memoryFacts`) — 기간 안의 **지난 일정**(반복 일정 제외)과
  **해낸 버킷리스트**를 같은 낱말로 골라(각 10개) 근거에 붙인다. 대화엔 "제주" 가 없어도 "제주도 여행" 일정으로
  "제주도 언제 갔지?" 에 답한다. 사진엔 **찍은 곳**이 붙는다(`🖼️ 사진 📍경기도 용인시기흥구`) — 좌표를 앱 지도와
  같은 `duri/data/*.geojson` 으로 시군구(한국)·나라로 바꾼다(`places.mjs`, 외부 API 없음, 읽기 전용).
  install.sh 가 그 두 파일을 설치 폴더 `data/` 로 복사한다. 없으면 장소만 빠진다. 낱말은 조사를 떼고("어니언에서"→"어니언") 끝 글자도 떼어
  ("제주도"→"제주") 찾고, "얘기"·"무슨" 같은 뜻 없는 낱말은 버린다.
- **기억 답은 두 번에 나눠 온다** — recall 로 정해지면 먼저 "잠깐만! 찾아볼게승~ 🐴" 를 보내고, 찾아서 답한다. 답엔
  **그날 사진 한 장**이 붙는다(`recallPhoto`): 낱말이 맞는 일정의 날 → 그 말을 한 대화가 있던 날 → 찍은 곳·캡션이 맞는
  사진 순으로 찾아 그날 가운데쯤 찍은 것. "봉천동" 처럼 동 이름은 사진 장소(시군구)에 안 맞아서 날로 찾는다. 날짜는
  'N월 N일' 로 말하고 그때를 떠올리는 한마디를 붙이게 했다. 부르는 말은 `@당이`·`@당`·`@당아`·`@당야`·`@당이야`.
- **사진 가져오기(photos)는 사진을 다시 올리지 않는다.** 백업에서 찍은 곳(시군구·나라)·캡션·기간으로 고른 사진의
  **seq 만** 당이 메시지의 `botPhotos` 로 보내고, 앱(`duri/index.html` 의 `dangiPhotos`)이 **자기 기기 캐시의 원래 사진**을
  말풍선 안 격자로 그린다 — 지도 탭 지역 앨범과 같은 재료다. 다시 올리면 PC 백업에 같은 사진이 두 번 저장되고 지도
  핀도 두 개가 되며, 앱이 사진 보낸 사람 "🤖 당이" 를 상대 이름으로 배운다. 그래서 캐시에서 정리된 옛 사진(최근 2000개
  밖)은 **PC 가 빌려준다**: 당이가 보여 주는 사진은 **전부** 원본을 같은 문구로 암호화해 서버 `/_duri/lend` 에
  7일 맡기고(채팅 버퍼 밖 — seq 가 없어 백업·지도·알림에 안 겹친다) 열쇠 `{seq,key,iv,mime}` 를 `botLend` 로 싣는다.
  PC 가 꺼져 있으면 당이도 자고 있으니 따로 요청 경로는 두지 않았다. 7일 지나면 앱이 "당이에게 다시 물어봐 주세요".
  처음엔 "커서보다 1800 넘게 옛 것만" 빌려줬는데, 폰 캐시는 기기마다 달라(새 폰·지운 캐시) 두 달 전 세종 사진 5장이
  하나도 안 뜬 적이 있어 전부로 바꿨다(앱은 캐시에 있으면 그걸 먼저 쓴다).
  25MB 넘는 원본은 빌려주지 않는다. 많으면 기간 전체에 고르게 6장, "하나 보여줘"·"두 장" 이면 그만큼(`countSaid`). 작은 모델이 "사진 보여줘" 를 unknown 으로 고르는
  일이 있어, 사진을 달라는 말이 분명하면 코드가 photos 로 돌린다(`PHOTO_ASK`).
- 말한 사람 이름은 긴 지시문 뒤 별도 시스템 메시지로 준다(앞부분이 같아야 모델 서버가 재사용한다).

- **운동 인증은 앱의 💪 와 같은 레코드**를 고친다(`wk`+YYYYMM+이름해시, `kind:"workout"`). id 를
  만드는 `whoKey` 가 앱과 같아야 해서 테스트가 `duri/index.html` 의 함수를 직접 꺼내 비교한다.
  체크는 **말한 사람 것만**, 앞으로 올 날은 안 된다. 날짜표는 일정용(오늘부터 60일)이고 지난 7일은
  "운동 인증에만" 이라고 따로 준다 — 날짜표에 섞었더니 "이번 주"·"토요일" 까지 지난 날을 골랐다.
- 주간 요약은 모델이 날짜를 세지 않고 `week:"this"|"last"` 만 고른다(월~일, 이번 주는 오늘까지).
  날짜를 프롬프트에 적어 줬더니 "이번 주 일정" 까지 그 날짜를 베꼈다. 그래도 작은 모델은 "이번 주
  일정" 에 운동 요약을 고르기도 해서, **요청에 운동 낱말(`FIT_WORDS`)이 없으면** 운동 동작을
  일정 동작으로 돌린다(fitlist → list, fit/unfit → 되묻기).

- **페르소나는 말(馬)이다** — 본명 다그당스, 애칭 당이, 3살, ESFJ. 사과랑 각설탕을 좋아하고
  쫑이랑 빵이에게 충성하는 다정하고 세심하고 귀여운 말. "푸히힝" 웃고 말끝이 "~승"(좋승~, 알겠승!). 잡담 답만 이 말투고, 일정 추가·목록 같은 확정 문구는 코드가
  만든다(모델이 날짜를 지어내지 못하게). 날씨·뉴스처럼 지금 정보는 모른다고 답하게 했다.

- **PC가 꺼져 있으면 앱이 바로 `💤 당이가 자고 있어요` 라고 알린다.** 서버의 `welcome`·
  `presence` 에 싱크가 붙어 있는지(`sink`)가 실려 오고, 앱(`DANGI_RE`)이 그걸 보고 그 화면에만
  그린다(전송·저장 안 함). 그 명령은 PC가 켜진 뒤에도 **실행하지 않는다**(10분 넘게 지난 명령은
  조용히 버린다) — 나중에 한꺼번에 실행되면 헷갈린다.
- `@당이`·`@당`·`@당아`·`@당야`·`@당이야` 뒤엔 공백·쉼표·느낌표나 끝이 와야 한다(`@당근`·`@당아지` 는 명령이 아니다). 규칙은 데몬
  (`assistant.mjs` 의 `TRIGGER`)과 앱(`DANGI_RE`) 두 곳에 있다 — 같이 고칠 것.
- **모델은 할 일만 고르고, 날짜·검증은 코드가 한다.** 프롬프트에 오늘부터 60일치
  날짜·요일 표와 앞뒤 일정 목록(e1, e2… 별칭)을 주고 JSON 하나만 받는다. 날짜표 밖·
  없는 별칭·잘못된 시간은 실행하지 않고 "이해하지 못했어요" 로 답한다.
- **옮기기·삭제는 확인을 받는다**(같은 사람이 10분 안에 `@당이 응`). 반복 일정은
  건드리지 않는다(캘린더 탭에서). 삭제하면 웹앱처럼 그 일정의 댓글도 지운다.
- 만든 일정은 `/일정` 명령과 같다: 기본 **공통**, `owner` = 말한 사람. "쫑이의 레슨" 처럼 한 사람 일정이면
  `owner` = 그 사람, `shared:false` — 앱에서 그 사람 색(쫑 = 노랑)으로 보인다. 이름은 캘린더의 색 설정·일정
  주인에서 모은 목록(`people`)에 있는 것만 받고, 모델이 빠뜨려도 요청의 "쫑이의 …" 로 찾는다.
- **버킷리스트(`bucket`)·데이트 추천(`recommend`)** — 앱의 ✓ 버킷리스트(`kind:"bucket"`/`"bucketcanvas"`
  레코드)를 **읽기만** 한다. "뭐 남았어/뭐 했어/제주도 있어?" 는 코드가 목록을 정리해 답하고(모델은 todo·done·
  찾을 낱말만 고른다), "이번 주말 데이트 추천" 은 기억(recall)처럼 2단계 — 아직 안 한 항목(40개까지)·최근 해낸
  것·3주 안의 일정 없는 주말만 보여 주고 그 안에서 1~3개 고르게 한다. 가게 이름·날씨는 지어내지 않게 했다.
  로그엔 개수만 남긴다.
- **아침 브리핑(매일 08:00 KST)** — 데몬이 1분마다 시각을 보고 08:00~08:09 KST 에 그날 한 번, 오늘·내일
  일정(반복·여러 날 포함, 앱의 `calEventOnDate` 와 같은 판정)을 당이 말투로 채팅에 올린다. 일정은 코드가 고르고
  모델은 문장만 엮는다 — 모델 답에 오늘 일정의 제목·시각이 하나라도 빠지면 버리고 틀 문장을 보낸다. 보낸 뒤
  서버에 `brief-done {date}` 를 알려 **08:10 cron 의 "📅 캘린더" 리마인드를 건너뛰게** 한다(PC 가 꺼졌거나
  못 했으면 그 리마인드가 fallback 으로 올라간다). 마지막 날짜는 설치 폴더의 `.dangi-brief` 에 남겨 다시 띄워도
  두 번 하지 않는다. 브리핑 끝엔 **"📸 1년 전 오늘"** 이 붙는다(`onThisDay`) — 1~3년 전 같은 날의 일정·사진 수와
  찍은 곳·해낸 버킷리스트를 **코드가** 한 줄로 만든다(모델이 추억을 지어내지 않게). 그날 아무것도 없으면 안 붙는다.
  그 앞엔 **"🌡️ 오늘 날씨"** — 지역마다 하늘·지금 기온·낮/아침 기온·비 확률·미세먼지 한 줄(`weather.mjs`, util/brief 와
  같은 Open-Meteo 를 PC 에서 바로 부른다, 비 30% 이상이면 우산·미세먼지 나쁨이면 마스크). 역시 코드가 만든다. 지역은
  설정 `assistant.weather: [{ "name", "lat", "lon" }]`(기본 청주·용인 시청, `false` 면 끔). 못 가져온 지역은 그 줄만
  빠진다. 이 PC 는 IPv6 가 막혀 있어 Node fetch 가 유럽 서버에 ETIMEDOUT 을 내므로 데몬이 시작할 때
  `setDefaultAutoSelectFamilyAttemptTimeout(2000)` 을 건다(curl 은 됨).
  시각은 설정 `assistant.briefing`("HH:MM", `false` 면 끔, env `DURI_BRIEF`). 지금 해 보려면
  `@당이 브리핑`. 로그엔 개수만 남긴다.
- **다그당스 이모티콘** — 매번 붙이지 않고 **필요할 때만** 쓴다: 잡담에서 마음을 표현할 말일 때(잘 자 → "잘 자승~",
  힘들어 → "토닥토닥", 고마워 → "고마웁승", 생일·사랑해·화이팅·배고파·퇴근…, 다그당스 4 는 안녕·히히·>_<·헐·귀여워·대박·우와·알림·신나·테니스·수고…)와
  "이모티콘 보내줘"(다그당스 3·4 중 하나).
  일정·운동·브리핑·추천·오류 같은 일 답엔 안 붙인다. 고르는 건 코드(`chatSticker`)다.
  글과 **같은 메시지**에 `botSticker:{pack,n}` 로 싣는다 — 따로 보내면 알림이 두 번 온다. `sticker` 필드가 아닌 건
  옛 앱이 이모티콘만 그리고 당이를 상대 이름으로 배우지 않게 하려고다. 백업엔 그 메시지의 `sticker` 로 남는다.
- **반복(`repeat`)**: "11월이랑 12월 모든 수요일" 은 모델이 요일과 달(`months`)만 고르고 날짜는 코드가 센다
  (지난 날 제외, 60개·1년까지). 기간을 날짜로 고르게 했더니 날짜표(60일) 안에서 잘라 12월 말을 빠뜨렸다.
  여러 개는 되묻고 `@당이 응` 에 한꺼번에 넣는다. 서버가 10초에 30프레임까지라 데몬이 400ms 간격으로 보낸다.
- 답은 이름 `🤖 당이` 의 시스템 메시지다. 앱은 이 이름만 가운데 알약이 아니라 **갈색 말풍선 + 프로필
  (다그당스1 07번 얼굴)** 로 그린다(`duri/index.html` 의 `DANGI_NAME` — 이름을 바꾸면 둘 다). 두 사람
  이름과 겹치면 안 된다.

켜기 — PC에 로컬 모델 서버를 띄우고 설정에 `assistant` 를 넣은 뒤 데몬을 다시 시작한다.
지금은 **llama.cpp `llama-server`(Vulkan, 내장 GPU)** 를 쓴다. Ollama 도 그대로 된다(`api` 를 빼면 Ollama).

```bash
# llama.cpp 릴리스(ubuntu-vulkan-x64)와 모델을 홈에 받는다 — sudo 필요 없음
mkdir -p ~/llama.cpp/models && cd ~/llama.cpp
gh release download <태그> -R ggml-org/llama.cpp -p 'llama-*-bin-ubuntu-vulkan-x64.tar.gz' && tar xzf llama-*.tar.gz
ln -sfn ~/llama.cpp/llama-<태그> ~/llama.cpp/current
B=https://huggingface.co/google/gemma-4-26B-A4B-it-qat-q4_0-gguf/resolve/main   # 당이(26B MoE, 2026-10-30~)
curl -fL -o models/gemma-4-26B-A4B-it-qat-Q4_0.gguf $B/gemma-4-26B_q4_0-it.gguf          # 14.4GB
curl -fL -o models/mmproj-gemma-4-26B-A4B-it.gguf $B/gemma-4-26B-it-mmproj.gguf          # 1.2GB
B=https://huggingface.co/ggml-org/gemma-4-E4B-it-GGUF/resolve/main                     # 예비(E4B)
curl -fL -o models/gemma-4-E4B-it-Q4_0.gguf $B/gemma-4-E4B-it-Q4_0.gguf                  # 4.6GB
curl -fL -o models/mmproj-gemma-4-E4B-it-Q8_0.gguf $B/mmproj-gemma-4-E4B-it-Q8_0.gguf    # 560MB
~/llama.cpp/current/llama-server --list-devices    # Vulkan0: AMD Radeon 680M 이 보여야 한다
```

`~/.config/systemd/user/llama-server.service`(26B) 로 상시 띄우고(`systemctl --user enable --now llama-server`),
**5분 안에 세 번 죽으면**(메모리 부족 등) 예비 `llama-server-fallback.service`(E4B)가 같은 8090 으로 대신 뜬다.
데몬은 주소가 같아 바뀐 줄 모른다. 공통 플래그는 `-ngl 99 -fa on -c 8192 -np 1 -t 8 --cache-reuse 256
--chat-template-kwargs '{"enable_thinking":false}' --host 127.0.0.1 --port 8090`(아래 `<공통>`).

```ini
# llama-server.service
[Unit]
StartLimitIntervalSec=300
StartLimitBurst=3
OnFailure=llama-server-fallback.service
[Service]
ExecStart=%h/llama.cpp/current/llama-server -m %h/llama.cpp/models/gemma-4-26B-A4B-it-qat-Q4_0.gguf --mmproj %h/llama.cpp/models/mmproj-gemma-4-26B-A4B-it.gguf <공통>
Restart=always
RestartSec=10
RestartMode=direct   # 이게 없으면 죽을 때마다 OnFailure 가 불려 둘이 번갈아 뜬다(systemd 254+)

# llama-server-fallback.service — enable 하지 않는다(OnFailure 로만 뜬다)
[Unit]
Conflicts=llama-server.service   # 본 서비스를 start 하면 예비는 내려간다
PartOf=llama-server.service      # 자는 시간의 stop llama-server 가 예비까지 재운다
[Service]
ExecStart=%h/llama.cpp/current/llama-server -m %h/llama.cpp/models/gemma-4-E4B-it-Q4_0.gguf --mmproj %h/llama.cpp/models/mmproj-gemma-4-E4B-it-Q8_0.gguf <공통>
Restart=on-failure
```

예비로 넘어갔으면 원인을 고친 뒤 `systemctl --user reset-failed llama-server && systemctl --user start llama-server`
(5분 안에 다시 켜면 횟수 제한에 걸려 거절된다). 지금 어느 모델인지는 `curl -s 127.0.0.1:8090/props` 의 `model_path`.
손으로 예비로 내리려면 `systemctl --user start llama-server-fallback`.

```json
"assistant": { "enabled": true, "api": "llama", "llama": "http://127.0.0.1:8090" }
```

Ollama 로 돌릴 땐 `"assistant": { "enabled": true, "ollama": "http://127.0.0.1:11434", "model": "gemma4:e4b", "keepAlive": "1h" }`
(`ollama pull gemma4:e4b`, 받기 9.6GB, 올리면 RAM 약 10GB). Ollama 가 저장한 gemma4 파일은 llama.cpp 가 못 연다
(텐서 구성이 다르다) — 그래서 GGUF 를 따로 받는다.

**자는 시간** — 매일 03:00~06:00 KST 엔 모델 서버를 끈다(YOUTUBE 워크스페이스의 crontab →
`scripts/dangi-sleep.sh sleep|wake`, 06:00 기상은 그쪽 나레이션 작업이 남았으면 최대 60분 늦어진다). 데몬은
시각이 아니라 **상태**로 판단한다 — 모델 서버에 연결이 안 되거나 503(모델 올리는 중)이면 "자는 중"
(`ModelAsleep`)이라 `@당이` 에 "😴 당이는 새벽 3시~6시에 자고 있어요" 로 답하고(새벽 3~7시 밖이면 "지금 자고
있어요"), 사진 설명은 실패로 세지 않는다. 타임아웃·500 같은 건 그대로 고장으로 알린다. 싱크(`duri-sink.service`)는
계속 돈다.

env 로는 `DURI_ASSISTANT=1` / `DURI_MODEL_API` (`llama`|`ollama`) / `LLAMA_URL` / `OLLAMA_URL` / `DURI_MODEL` /
`DURI_KEEP_ALIVE`. `api` 를 안 적으면 Ollama, 모델을 안 적으면 `qwen2.5:7b`, `keepAlive` 를 안 적으면 `1h`.

**벤치마크** — `node _src/duri-sink/bench.mjs http://127.0.0.1:8090` (모델 서버가 떠 있어야 한다, `npm test` 아님).
가짜 캘린더로 일정·운동·잡담·반복/누구 일정·버킷리스트·추천 분류 30문항 + 기억 찾기 4 + 기록 보고 답하기 3 + 추천 답 2.
2026-10-25 gemma4 E4B(llama-server Vulkan): 39/39 세 번 연속, 이어지는 답 평균 3.0–3.2초. 2026-10-30 gemma4 26B-A4B: 39/39,
2.9초. 문항을 고치면 여기 점수도 갱신한다.

**비전(사진 읽기) 켜기 (2026-10-27)** — 같은 모델에 `--mmproj`(`mmproj-gemma-4-E4B-it-Q8_0.gguf`, 560MB, 같은
HF 저장소)를 붙이면 이미지 입력이 된다(`/props` 의 `modalities.vision: true`). 메모리 +0.4GB(서버 약 3.9GB).
사진 10장 캡션 시험: 폰 원본(2~3.5MB)은 이미지 1142토큰 → **장당 18~25초**, 작은 이미지는 4~8초, 평균 19초.
설명 품질은 쓸 만하다("붉은 국물에 면과 두부, 계란이 든 냄비 요리" 등). 글 벤치는 켜고 끈 상태 모두 29~30/30으로
차이가 없다(틀리는 문항이 실행마다 다른 요일→날짜 약점).

**사진 설명 달기(`captions.mjs`)** — 비전이 켜져 있으면(`/props`) 데몬이 30초마다 "당이가 10분 넘게 안 불렸나"를
보고, 한가하면 사진 한 장(최근 것부터, jpg·png만)을 보고 `{desc, tags}` 를 `DuriStorage/captions.json` 에 남긴다.
명령과 같은 줄(`assistant.idle`)에 서서 모델을 겹쳐 부르지 않는다 — 설명 다는 중에 누가 부르면 그 한 장(최대 25초)만
기다린다. 실패는 세 번까지. 처음 258장은 2시간 남짓, 그 뒤엔 새 사진만. **찾을 때는 비전을 안 쓴다** — `archive.mjs`
가 이 파일을 읽어 사진 줄(`🖼️ 사진 [회 접시] 📍…`)과 사진 찾기 낱말에 섞을 뿐이라 "바다 사진 보여줘"·"회 먹은 날
언제지" 가 된다. 달별 `metadata.json`(정본)은 건드리지 않는다. 끄려면 설정 `assistant.captions: false`.

**실행기 고르기 (2026-10-25, Ryzen 9 6900HX + Radeon 680M, 실제 당이 프롬프트·가짜 캘린더 20문항, gemma4 E4B)**

| | 정답 | 긴 지시문을 처음 읽을 때 | 이어지는 답 | RAM |
|---|---|---|---|---|
| llama-server Vulkan (Q4_0) | 18/20 | 6.1초 | 평균 1.9초 | 약 5GB |
| Ollama 0.24 (CPU만) | 17/20 | 38.4초 | 평균 2.8초 | 약 10GB |

Ollama 0.24 는 이 내장 GPU 를 안 쓴다(로그 `offloaded 0/43 layers to GPU`). 지시문 2900토큰 읽기 속도가
CPU 72 tok/s → Vulkan 312 tok/s, 쓰기는 14.6 → 19.7 tok/s (`llama-bench -p 2900 -n 64`).
**gemma4 는 속생각(thinking)을 꺼야 한다** — 켜 두면 JSON 한 줄에 150~200토큰을 먼저 써서 평균 17초가 된다.
서버 옵션과 요청(`chat_template_kwargs.enable_thinking:false`) 양쪽에서 끈다.
