# animation-techniques — 사람 애니메이터의 기법과 AI 파이프라인 적용

사람이 2D 캐릭터 애니메이션을 만들 때 실제로 쓰는 기법을 리서치해서(2026-07),
우리 파이프라인(12~24프레임 1~2초 루프 이모티콘)에 적용 가능한 형태로 정리했다.
각 항목의 **→ AI**가 파이프라인 매핑이다. 실측 교훈은 `lesson_learned.md`.

## 0. 핵심 결론 먼저

사람 애니메이터의 생산성 비결은 **"적게 그리고 영리하게 배치"**다.
프레임을 많이 생성하는 쪽이 아니라, **적은 유니크 프레임(6~12장)을
pose-to-pose 순서로 생성하고, 타이밍·홀드·재사용(리미티드 기법)을 조립
단계에서 코드로 구현**하는 쪽이 품질·일관성·비용 모두 유리하다.
우리가 겪은 보일링(프레임 간 튐)은 straight-ahead(1→N 순차 생성)의
고질병이며, 사람들은 애초에 그 순서로 그리지 않는다.

## 1. 작업 순서 — pose-to-pose가 표준

- **straight-ahead**(1번부터 순서대로) vs **pose-to-pose**(중요 포즈 먼저,
  사이는 나중에). 전자는 비율이 무너지고 타이밍 제어가 안 돼서, 캐릭터
  연기(이모티콘 포함)는 후자가 표준이다.
- 실무 순서: 썸네일 → **키 포즈(extremes**, 동작의 의도를 말하는 극단) →
  **브레이크다운**(두 키 사이의 경로·호·방향 전환을 결정하는 중간 핵심) →
  **인비트윈**(나머지 기계적 중간) → 클린업. 중요도 순으로 계층적으로 채운다.
- **타이밍 차트**: 키 드로잉 옆에 눈금을 그려 인비트윈의 *배치*를 지시한다.
  눈금이 키 근처에 몰리면 그 근처에서 느려진다(ease). 패턴: ease-out(가속),
  ease-in(감속), easy ease(양끝 촘촘), favor(한쪽 키에 치우친 인비트윈).
- **→ AI**: 생성 순서를 사람처럼 바꾼다 — ① 극단 포즈 2~4장 먼저 생성·검수
  ② 키 쌍을 **양쪽 이웃 레퍼런스**로 브레이크다운 생성 ③ 필요한 곳만
  인비트윈. 1→N 순차 생성(현재 cut 방식)은 드리프트를 누적시킨다.
  인비트윈 프롬프트에 "A포즈 70% : B포즈 30% 지점" 같은 favor를 명시한다.

## 2. 디즈니 12원칙 — 이모티콘에서 체감 큰 순서

(출처: *The Illusion of Life*, Frank Thomas & Ollie Johnston)

1. **Squash & Stretch** — 찌그러뜨리고 늘리되 부피 보존. "탱글탱글함"의
   근원. → 극단 프레임에만 "납작하게/길쭉하게, 부피 유지"를 강하게 지시.
2. **Anticipation(예비동작)** — 큰 동작 직전 반대 방향으로 움츠림. 없으면
   동작이 뚝 끊긴다. 국내 강좌도 "동작준비–동작–동작마감" 3단계로 가르친다.
   → 키 포즈 기획을 항상 예비→메인→정착 구조로.
3. **Slow in/out (ease)** — 등속 금지. → 생성 장수가 아니라 **프레임 배치·
   hold·프레임별 duration**으로 구현한다.
4. **Timing** — 프레임 수가 무게를 결정: 적으면 경쾌, 많으면 둔중.
   → 같은 키 세트에서 인비트윈 수만 바꿔 캐릭터 성격 변주.
5. **Exaggeration** — 360px(실표시 더 작음)에서는 현실보다 훨씬 과장해야
   읽힌다. 눈물은 폭포로. → 과장 지시는 극단 프레임에만 강하게.
6. **Follow-through & Overlapping** — 몸이 멈춰도 귀·볼살은 1~3프레임 늦게
   멈춘다. → 부속물 움직임을 몸보다 1~2프레임 지연시켜 지시(§4 오프셋).
7. **Arcs** — 팔·고개는 직선이 아니라 호로 움직인다. 브레이크다운이 호를
   결정. → 브레이크다운 포즈 문장에 "직선 중간이 아니라 위로 볼록한 호 위".

보조: Staging(1동작 1감정, 실루엣으로 읽히게), Secondary action(웃으며
어깨 들썩), Appeal. Solid drawing은 플랫 이모티콘에선 비중 낮음.

## 3. 리미티드 애니메이션 — 적은 장수로 살아있게 (최대 지렛대)

일본 TV 아니메가 초당 8~12장으로 살아있는 움직임을 만드는 기법들:

- **2s/3s 촬영**: 같은 그림을 2~3프레임 유지(24fps 기준 초당 12장/8장).
  한 컷 안에서도 빠른 구간만 1s, 느린 구간은 3s로 혼용한다.
- **홀드(止め)**: 정지 자체가 "모으기(타메)"로 읽혀 다음 동작을 강조.
- **부분 애니메이션**: 몸은 홀드, 일부만 교체 —
  입은 닫힘/반열림/열림 **3장**(구파쿠), 눈 깜빡임도 뜸/반/감음 **3장**(메파치).
- **스미어 프레임**: 빠른 이동을 1~2프레임의 왜곡 그림으로 연결 —
  길게 늘인 잔상형(펀치·홱 돌리기) / 팔을 3~4개 겹쳐 그리는 멀티플형
  (손 흔들기). 정지컷으론 이상해도 재생하면 속도감이 산다.
- **모션 라인·이펙트**: 움직임 대신 속도선·먼지·반짝이를 홀드 위에 얹기.
- **→ AI**: **유니크 6~12장 + 홀드/재사용으로 24프레임을 채우는 설계를
  기본값으로.** (a) 말하기 = 몸 1장 + 입 3장 교체 (b) 대기 루프 = 몸 1장 +
  눈 3장 (c) 빠른 동작 = 키 2장 + 스미어 1장("팔이 여러 개 겹친 잔상")
  (d) APNG 프레임별 delay를 2~3배로 늘려 2s/3s 구현 — 인코더가 이미
  프레임별 delay를 지원하므로 조립 규칙만 추가하면 된다.

## 4. 루프/사이클

- **심리스 루프**: 마지막 프레임 다음이 첫 프레임과 이어져야 한다. 실무는
  "마지막 = 첫 프레임 복사, 재생 시 중복 제거". 위치·크기 전부 일치해야 함.
- **핑퐁 루프**: A→B→A 왕복 재생. 끄덕임·갸웃·숨쉬기·두근처럼 왕복형
  동작은 **편도만 그리고 역순 재생으로 절반이 공짜**. 관성이 필요한
  동작(던지기)엔 부적합.
- **오프셋 레이어링**: 귀·리본·꼬리의 사이클을 몸보다 1~3프레임 지연시켜
  겹치면 유기적으로 보인다.
- 루프 정점에 2~3프레임 홀드를 넣으면 리셋이 의도적으로 보인다.
- **→ AI**: (a) 루프 인비트윈은 "마지막 키→첫 키" 구간도 반드시 생성
  (키를 원형으로 배치) (b) 왕복형은 편도 6~8장 생성 후 핑퐁 조립 —
  유니크 장수 절반 (c) 부속물 지연은 프레임 인덱스 시프트 합성으로 후처리.

## 5. 이모티콘 작가 실무 관행

- 툴: 포토샵 타임라인·Clip Studio·Procreate — 공통적으로 **어니언 스킨**
  (앞뒤 프레임 반투명 표시)으로 인비트윈을 그린다. 원본 캔버스는 1080px대로
  크게, 360/540으로 축소 출력. (우리 파이프라인의 1024 생성→360 축소와 일치)
- 유니크 드로잉 6~12장, 12fps 안팎, 프레임별 duration 개별 조정(0.07~0.15초).
  부드러움보다 **동작의 읽힘**이 우선.
- LINE은 **1번째 프레임이 스토어 대표 정지컷** — 감정이 가장 잘 드러나는
  컷을 첫 프레임에 배치한다. (카카오 제안도 대표 프레임 인상이 중요)
- **스테이플 동작 레시피** (유니크 장수 기준):
  - 인사(손 흔들기): 팔 올림 예비 1 + 좌/우 극단 2 + 스미어 1 → 핑퐁. **4~5장**
  - 끄덕임: 위/아래 극단 2 + 중간 1 → 핑퐁 + 아래서 홀드. **3장**
  - 하트/두근: 하트 소→대 극단 2 + 인비트윈 1~2 + 최대에서 홀드 + 반짝
    이펙트 오프셋. **3~4장**
  - 울음: 몸 홀드 1 + 눈물만 3~4장 사이클 + 어깨 들썩 2장 핑퐁. **5~6장**
  - 웃음(빵터짐): 몸 기울기 극단 2 핑퐁(2s, 빠르게) + 입 크게 홀드 +
    "ㅋㅋ" 이펙트 오프셋. **3~4장**

## 6. 선행 사례 (생성 모델 쪽)

- **Generative Inbetweening** (UW+DeepMind 2024, [arXiv:2408.15239](https://arxiv.org/abs/2408.15239)):
  두 키프레임에서 양방향 샘플링을 융합해 사이 프레임 생성 — "양쪽 이웃
  조건화 인비트윈"의 학술 검증.
- **ToonCrafter** (SIGGRAPH Asia 2024, [프로젝트](https://doubiiu.github.io/projects/ToonCrafter/)):
  카툰 특화 생성 보간. 시작·끝 프레임 + **스케치 가이드**로 중간 포즈·호
  통제 — 애니메이터의 브레이크다운을 조건 입력으로 옮긴 형태. B경로 도입
  시 1순위 후보.
- ComfyUI 실무: AnimateDiff + FILM 보간으로 "생성 → 보간 배가 → 조립"이
  커뮤니티 표준.

## 7. 우리 파이프라인 다음 버전 (리서치 종합)

1. **기획**: 동작을 "예비→메인→정착(→복귀)" 키 3~4장 + 각 키의 hold 길이
   + favor를 타이밍 차트처럼 명세 (포즈 스크립트의 진화형).
2. **키 포즈 생성**: 시트 조건화로 극단만 생성·검수. 첫 프레임 = 대표 감정컷.
3. **브레이크다운**: 키 쌍 양쪽 레퍼런스 + 호 지시로 생성.
4. **인비트윈**: 필요한 곳만. 빠른 구간은 스미어 1장 또는 생략(2s/3s),
   느린 구간은 favor + hold.
5. **조립**: 핑퐁·부분교체·오프셋 합성으로 유니크 8장 → 24프레임 확장,
   프레임별 delay로 ease, 마지막→첫 구간 검증(루프 diff).

구현 관점 요약: cut 명령을 "프레임 N개 순차 생성"에서 **"키 생성 →
브레이크다운 → 조립 규칙(핑퐁/홀드/delay)"**의 3단으로 개편하는 것이
다음 큰 단계다. 인코더(apng.mjs)는 프레임별 delay만 노출하면 준비 끝.
