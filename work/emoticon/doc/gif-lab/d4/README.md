**이미지는 저장소에 없다.** 원본 스티커·부품·프레임·출력은 전부 로컬 `~/dageudangs-lab/work/d4/<종>/` 이다(사용자 지시).
여기에는 스크립트(`tools/`)와 프롬프트(`prompts/`)만 있다. 16종 동작 표는 [`../../../emoji.md`](../../../emoji.md) 「다그당스 4 움직이는 이모티콘」.

## 공통 흐름

1. `split_sticker.py <스티커>.png <종>/split` — 투명 스티커를 가장 큰 덩어리(캐릭터)와 나머지(글자·효과)로 가른다.
   글자 없는 캐릭터 `char.png`, image_gen 레퍼런스용 `char_ref.png`(흰 바탕, 3배), 효과 부품 `parts/NN.png` + `parts.json`(원래 위치).
2. 움직임 — 종의 분류에 따라 아래 셋 중 하나.
3. `cutout.py` — 흰 바탕 프레임 → 투명 PNG(테두리에서 flood fill, 눈 흰자 유지). **원본 = 투명 PNG 24장.**
4. `fx_overlay.py` — 스티커에서 떼어 낸 효과(음표·하트·먼지)를 코드로 움직여 얹는다.
5. `d4_export.py <frames> <out> --ms …` — 미리보기 GIF(흰)·APNG(투명) 360², 카카오 GIF, LINE APNG(+main·tab), `report.md`(규격 ✓/✗).
   `--text` 는 글자를 얹을 자리만 있다(아직 안 쓴다). 최종 형식을 정하면 같은 프레임에서 다시 뽑는다.

## 카카오 트랙으로 가려면

카카오는 생성형 AI 이모티콘 입점을 2023-09부터 사실상 막고 있다(`../../kakao-emoticon-guide.md` §1). 지금 흐름에서 image_gen 이 들어가는 곳은
① 부품 그리기(01·14)와 ② 14 의 클린업(24장 전체를 다시 그림)이고, ③ 원본 스티커 dageudangseu-4 가 처음 어떻게 그려졌는지도 확인해야 한다(AI 로 만든 것이면 그것부터 문제다).
반대로 움직임·타이밍·효과 배치·출력은 전부 코드라 문제가 되지 않는다. 그래서 카카오용은 **손그림 원화 + 리깅**이어야 한다 —
사람이 기준 포즈 한 장과 리그 부품(다리 없는 몸·팔·다리, 아랫면을 닫은 이음매)을 그리고, `arm_rig`·`parts_rig` 처럼 코드가 각도를 돌린다.
클린업은 AI 대신 사람이 이음매·무릎만 손보거나 하지 않는다. 07 처럼 **원화를 통째로 움직이고 효과 부품만 얹는 A 분류**가 가장 쉽게 옮겨진다(AI 단계 0).
B·C 는 사람이 부품을 그리는 품이 든다. 제출 때는 AI 사용 여부를 정직하게 밝히고, 정책이 바뀌었는지 이모티콘 스튜디오에서 다시 확인한다.
