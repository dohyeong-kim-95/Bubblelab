# interior.bubblelab.dev — 집안일 동선 계산기

3D 평면에 가구를 놓고 **빨래(넣기·건조·널기·수납)·설거지·분리수거·청소** 같은 집안일을 할 때
걷는 거리를 잰다. 담금질 최적화가 움직일 수 있는 가구를 옮겨 주당 거리를 줄인다.
도면 초안은 LLM 에게 맡긴다 — 화면의 📄 도면 JSON → 🤖 LLM 요청문 복사를 붙여 넣고
"우리 집은 32평 판상형이고…"처럼 말하면 이 형식의 JSON 을 써 준다. 받은 걸 붙여 넣고 불러오기.

비공개 서브도메인(`CONFIDENTIAL_SUBDOMAINS`, noindex)이고 로그인·서버 저장은 없다 — 도면은
브라우저 localStorage(`interior.plan.v1`)에만 있다.

## 파일

| 파일 | 하는 일 |
| --- | --- |
| `engine.js` | **순수 계산 전부** — 놓기 규칙, 격자 A* 길찾기, 동선 점수(`evaluate`), 최적화(`optimize`), 도면 검사(`normalizePlan`) |
| `app.js` | three.js 화면·끌어 옮기기·점수판·JSON 대화상자 |
| `opt-worker.js` | 최적화를 워커에서 돌린다(화면 안 멈춤) |
| `prompt.js` | LLM 요청문(형식 설명 + 지금 도면) |
| `plans/sample.json` | 예시 도면(거실·주방·안방·욕실·다용도실·베란다) |

테스트는 `_infra/interior.test.mjs`. three.js 는 `/_shared/vendor/` 셀프호스팅.

## 도면 형식 (cm, 원점 왼쪽 위, x 오른쪽, y 아래)

- `room {w,d}` — 집 전체 바깥 사각형. 바깥 벽은 자동.
- `walls [{x1,y1,x2,y2,t?}]` — 안쪽 벽, 가로·세로 선분만. 문은 선분을 끊어서 비운다.
- `zones [{id,label,x0,y0,x1,y1}]` — 방 이름표이자 울타리. 가구의 `zone`(하나 또는 배열) 밖으로는 최적화가 안 옮긴다.
- `items [{id,label,kind,x,y,w,d,h,rot,fixed?,wall?,pass?,zone?}]` — x,y 는 **중심**, rot 0 이면 앞면이 +y.
  `wall` 은 등을 벽에 붙이는 가구, `fixed` 는 배관·붙박이(최적화 제외, 화면에서 📌), `pass` 는 길을 막지 않는 한 점(현관 등).
- `tasks [{id,label,perWeek,stops:[item id…]}]` — 차례로 들르는 곳과 주당 횟수.

## 계산 규칙

- 사람은 가구 **앞면 앞 35cm**(`ACCESS`)에 서서 쓴다. 들르는 곳 사이는 그 자리끼리 걷는다.
- 길은 10cm 격자 8방향 A*. 벽·가구를 **몸 반지름 20cm**(`BODY`)만큼 부풀려 피하므로 40cm 미만 틈은 못 지난다.
  못 가는 구간은 50m 벌점(`UNREACHABLE_CM`)으로 세고 화면에 ⚠ 를 띄운다.
- 점수 = Σ 할 일 (구간 거리 합 × perWeek). 분은 0.8 m/s 로 환산.
- 최적화는 20cm 격자로 빠르게 재며 2500번 시도한다(예시 도면 262m → 약 110m, 1초 안팎).
  움직임: 벽붙이는 벽 따라 미끄러뜨리기·다른 벽 면으로 옮기기, 나머지는 밀기·90° 돌리기·구역 안 아무 데나.
  겹침·방 밖·구역 밖·벽에서 떨어짐은 아예 받지 않는다. 시드가 같으면 같은 답.
- 함정: 벽에 붙인 자리를 5cm 로 반올림하면 깊이 64cm 가구가 벽에 2cm 박혀 전부 거절된다 — 벽붙이 좌표는 반올림하지 않는다.

## 한계

- 청소기 같은 "면 전체를 훑는 일"은 들르는 점 몇 개로 어림한다.
- 동선만 본다 — 채광·콘센트·문 여닫는 반경은 모른다. 그런 건 zone 을 좁히거나 📌 고정으로 막는다.
